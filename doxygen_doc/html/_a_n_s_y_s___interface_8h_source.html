16
17@brief File based interface between ANSYS and CSMP.
18
19To provide a file-based interface between the TETRA meshing tool from
20ANSYS Technologies Inc. and CSMP which also allows to extract parts of the
21input mesh selectively, assign material properties, boundary conditions
22and to rigorously test the incorporated mesh for its compliance with
23CSMP requirements.
24
25@author S.K. Matthai
26@author S. Geiger
27@author S.G. Roberts
28@date 2001
29
30@section design Design Intent
31
32File reading has been broken up into modules such that with possible
33changes only small bits of code must be recreated. Also files have been
34separated into text and binary input, such that the user-readable part
35is readily accessible in textformat while the bulk of the data reside
36in an efficiently readable binary file.
37
38
39@section applicability Applicability
40
41To files which have been written with a specific output module created
42specifically for CSP by ANSYS technologies (Ulrike Wolf, Berlin).
43
44
45@section participants Participants
46
47The ANSYS interface uses the classes VSet, FEM_Primitive and
48ModelTopology to store the information in which has been retrieved
49from file.
50
51
52@section implementation Implementation
53
54Two files: one human readable text (.asc = ASCII) file and a binary (.dat) file
55that can be transferred across platforms (Windows OSX, linux etc/).
56
57The regions and material file ('*.asc'):
58
59- model name (line break)
60
61- Comment line (header): 1. filename, 2. date of generaton
62
63- Number of labelled objects
64
65- Table with objects, element types, material ID values (rock types), number of elements (cells)
66
67@code
68 Object element-type material ID number-of-elements
69 LIV TETRA_4 3 760
70 BOXS TRI_3 0 2030
71 CURVES BAR_2 0 20
72@endcode
73
74The material ID facilitates the association of 'rock types' with model regions.
75
76- List of elements making up each region (numbered 0...n-1), preceded by region name and
77number of elements of region.
78
79@code
80 LIV_SMALL 6
81 12 13 14 15 16 17
82@endcode
83
84The binary file ('*.dat') contains:
85
861. NODE COORDINATE DATA (double):
87
88PX, PY, PZ records: preceded by a single unsigned long indicating the size of
89these records which (individually) contain (with or without line breaks):
90
91px: -> x-coordinates of the nodes
92py: -> y-coordinates of the nodes
93pz: -> z-coordinates of the nodes
94
95(all entries in these records have the format double and
96the node-IDs are implicit from 0 to nodes-1):
97
98Such records could be written as shown in the C++ code example
99below:
100
101@code
102double* ptr; // data pointer
103...
104unsigned long n0(0), n1(1);
105
106if ( (records=px.size()) > 0 && (ptr=const_cast<double*>(px.Data())) != NULL )
107 {
108 fwrite( (void*) &records, sizeof(unsigned long), 1, fp );
109 fwrite( (void*) ptr, sizeof(double), records, fp );
110 }
111else fwrite( (void*) &n0, sizeof(unsigned long), 1, fp );
112@endcode
113
1142. NODE FLAGS (int)
115
116PBFLAGS: Same record length as the record set above but in int32_t format.
117
118- if a node lies on a model boundary, a negative integer value
119 is assigned to identify that boundary uniquely in terms of the
120 named surface it belongs to. If the node is not located on a
121 model boundary, its int value is set to zero. If lines or curves were
122 specified on the model boundaries, edge nodes along these lines are
123 flagged by unique negative integers by analogy to the identifiers for
124 the edges in the ANSYS topology.
125
126 A boundary and edge numbering scheme for box-shaped models in CSP has
127 the following values (adhering to a righthand-rule coordinate system
128 where x points to the right, y points upward and z points to the front:
129
130@code
131#define BACK_BOTTOM -16 // BACK and BOTTOM
132#define BACK_RIGHT -17 // BACK and RIGHT
133#define BACK_TOP -18 // BACK and TOP
134#define BACK_LEFT -19 // BACK and LEFT
135#define BOTTOM_RIGHT -20 // BOTTOM and RIGHT
136#define TOP_RIGHT -21 // TOP and RIGHT
137#define TOP_LEFT -22 // TOP and LEFT
138#define BOTTOM_LEFT -23 // BOTTOM and LEFT
139#define FRONT_BOTTOM -24 // FRONT and BOTTOM
140#define FRONT_RIGHT -25 // FRONT and RIGHT
141#define FRONT_TOP -26 // FRONT and TOP
142#define FRONT_LEFT -27 // FRONT and LEFT
143@endcode
144
145
1463. BOUNDARY CONDITIONS APPLIED TO NODES (double)
147
148PBVALS: Analogous to the record sets above but in double format:
149
150- Corresponding to the non-zero flags from above, where a node is
151 located at a model boundary, a boundary value as previously assigned
152 to the ANSYS topological model can be stored in this data record.
153 If no value was assigned, this record will just hold zeroes.
154
155
1564. TYPE OF FINITE ELEMENTS (enum -> unsigned int)
157
158PELMT (0...e-1): Record is preceded by an unsigned long indicating
159record size (=number of finite elements in the mesh). 'pelmt'
160consists of a single record of (all as unsigned longs):
161
162- element-type identifiers (unsigned int) for each
163 finite element in the mesh. How they correspond to element
164 type strings is specified further below.
165
166 Dieser Eintrag vermeidet Doppeldeutigkeiten, die dadurch entstehen
167 koennten, dass es verschiedene Elementtypen mit der gleichen Anzahl
168 von Knotenpunkten gibt.
169
170
1715. MESH CONNECTIVITY (unsigned long)
172
173PLIST: Record preceded by an unsigned long indicating record size,
174a single record follows containing (all as unsigned longs):
175
176- node ids of each element in
177 counter-clockwise order (according to node numbering on reference elements).
178 The enlisted node numbers range from 0...nodes-1 as above.
179
180The elements are numbered implicitly and continuously by their position
181in the plist (there must be no jumps in the element ids).
182
183
184PFVERTS: Record preceded by unsigned long indicating record size, then a
185single record (all long, where negative numbers denote model boundaries):
186
187- neighbour elements
188 of each element in an order defined for each existing element
189 type (see further below, for tetrahedra and triangles, neighbors are
190 those elements touching the element's faces opposite of its corner nodes).
191 Neighbor elements are denoted 0...element-1. Where there are no neighbour
192 elements adjacent to the element's faces because the element lies on a model
193 boundary, a negative long is used to identify this boundary surface.
194
195
1966. MATERIAL IDENTIFIER FOR EACH ELEMENT = ROCK TYPE
197
198PMTRL: preceded by number of elements, associates each element with the
199material flag from the '*.asc' file such that properties can be assigned.
200
201Comments: leading hash key (# everything thereafter is ignored)
202
