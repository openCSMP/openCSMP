31@section motivation Motivation
32
33Since only one phase is propagated in the FiniteVolumeFluidPhaseVisitor,
34the saturation of the second phase must be computed afterwards, which
35is done by this simple interrelation, such that all saturation dependend
36properties can be computed afterwards. The user must define
37in the constructor of this object the saturation that was computed
38in the FiniteVolumeFluidPhaseVisitor (i.e., reference saturation) and
39the saturation which shall be computed by this interrelation (i.e., new oder
40second phase saturation) by subtracting the reference saturation from 1.0.
41
42
43Of course, the saturation of the second phase can also be computed by
44the FiniteVolumeFluidPhaseVisitor, which is, however, computationally
45more expensive than applying this interrelation.
46
47
48@section implementation Implementation
49
50The user must provide the character strings of the reference saturation
51(first character string in the constructor) and the saturation to be
52computed (second character string in the constructor) to the constructor
53of this interrelation.
54
55As part of the Interrelation base class, this interrelation is passed
56to the Model in the main() program. It should be done during the transient loop, such
57that the saturations are both constantly updated. Some functions of the
58FiniteVolumeFluidPhaseVisitor also require a reference to this interrelation,
59since the saturation of the second phase must be updated within the time-loop
60constantly. See the CSMP documentation for more detail on the Interrelation
61base class and their derived classes and the FiniteVolumeFluidPhaseVisitor
62documentation for details on the different member functions.
63
64
65@section examples Application Examples
66
67@code
68// oil is propagated, computing the water saturation <br>
69// when the interrelation is passed to the Model <br>
70ComputeSecondPhaseSaturation second_phase( p_ref, "saturation oil", "saturation water" );
71@endcode
