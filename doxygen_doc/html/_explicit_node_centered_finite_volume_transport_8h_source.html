107/**
108
109@class ExplicitNodeCenteredFiniteVolumeTransport ExplicitNodeCenteredFiniteVolumeTransport
110"generic_node_centered_finite_volumes\ExplicitNodeCenteredFiniteVolumeTransport.h"
111@author S.K. Matthaei
112@date 2002
113
114@section motivation Motivation
115
116The ExplicitNodeCenteredFiniteVolumeTransport module is provided to allow users
117to perform passive advection and advection of a single non-wetting
118phase in two-phase flow simulations. It represents the fastest but
119CFL dependent transport scheme for arbitrary FE meshes including
120different FE types and mixes of volume and surface elements.
121
122The scheme is also very tolerant in that no specific boundary conditions
123need to be applied. The value of the advected variable at inflow
124boundaries is not modified and governs what gets transported into
125the model domain.
126
127
128@section design Design Intent
129
130The scheme has been designed to capitalize on the new generic polytype
131CVFE technology that is part of CSMP.
132
133
134@section applicability Applicability
135
136Use the scheme if the transport velocity field is rapidly changing or
137invalidated by the transport itself. In this case the scheme is faster
138that the implicit scheme embodied in the FiniteVolumeTransport module
139which starts to pay off at about CFL=20 or greater.
140
141Do not use this scheme when the CFL condition based transport increment
142leads global advection steps that are smaller than about 1/1,000 of the
143model length in the direction of the flow. In this case the computations
144would be prohibitively slow.
145
146
147@section structure Structure
148
149The explicit advection scheme consists out of the three modules:
150
151ExplicitNodeCenteredFiniteVolumeTransport
152ExplicitFiniteVolumeAlgorithm
153ExplicitFiniteVolumeProcessor
154
155
156The user will only interact with the ExplicitNodeCenteredFiniteVolumeTransport module,
157but the ExplicitFiniteVolumeAlgorithm is used to manage the accumulation
158and output of the solution in each transport step, and the
159ExplicitFiniteVolumeProcessor class facilitates the generation of the
160finite-volume stencils from each finite element, so that the accumulation
161can proceed on an element by element basis and no FV mesh needs to be
162stored.
163
164
165@section collaboration Collaboration
166
167The scheme collaborates with the finite elements of the current model.
168
169
170@section consequences Consequences
171
172This implementation of the scheme cannot be restricted to Regions, but
173always needs to be applied to the entire model, i.e. Model.
174
175Currently it also only works for 3D models. Surface computations can
176still be done if the mesh consists entirely of surface elements in
1773D space.
178
179
180@section implementation Implementation
181
182The flux-balances are computed for all finite volumes including those
183which are located on the boundaries of the Region or Model to
184which the transport scheme is applied. They are compensated for also
185on all domain boundaries.
186
187
188@section examples Application Examples
189
190This is an example of how the second order accurate scheme is applied:
191
192@code
193 ExplicitNodeCenteredFiniteVolumeTransport explicit_advector( model, "porosity", "diffusivity",
194 "concentration", "velocity", second_order );
195
196 cout <<"\n\nadvectVariableExplicit: Configuring TRANSPORT simulation: ";
197 if ( second_order ) cout <<" IMPES: SECOND ORDER SCHEME."<< endl;
198 else cout <<" IMPES: FIRST ORDER SCHEME."<< endl;
199 cout <<"\nThe grid Courant number is "<< explicit_advector.CourantIncrement( sg ) << endl;
200 cout <<"\nEnter advection time: ";
201 double time_interval;
202 cin >> time_interval;
203
204 cout <<"\n\tMeasuring the time required to solve the advection problem."<< endl;
205 clock_t ticks = clock();
206 explicit_advector.AdvectVariable( model, time_interval );
207 ticks = clock() - ticks;
208 cout <<"\n\n\tCPU clock ticks used for advection step: "<< ticks << endl;
209@endcode
210
211*/

275/**
276
277Constructor for the single-phase passive advection scheme for slightly
278compressible flow without fluid density and viscosity variations. The
279ExplicitNodeCenteredFiniteVolumeTransport can be constructed for first- and second
280order calculations.
281
282Diffusion is only taken into account if second-order is chosen, because
283the first-order scheme already is so diffusive that adding an extra
284diffusion term makes little sense.
285
286@section arguments Input Arguments
287
288The ExplicitNodeCenteredFiniteVolumeTransport gains access via reference to the
289model to which it is applied to. The user needs to specify the piecewise
290constant element variables porosity, diffusivity and transport velocity
291as must be defined in the CSP_variables.txt file. The transported
292variable must be nodal since this explicit transport scheme is based
293on node-centered finite volumes.
294
295@section implementation Implementation
296
297The constructor creates minor storage array for repetitively used
298variables like the finite (pore) volumes, the flux balance for each
299FV cell and a vector<double> of FV_parameters called FV_stencil_data that holds
300the FV sector volumes, facet areas and facet normal fluxes which are
301always updated before the first advection step, when the CFL criterion
302is computed. This vector<double> will become redundant when the generic FV scheme
303has been optimized for speed.
304
305@section application Application
306
307Use ExplicitNodeCenteredFiniteVolumeTransport as constructed with this particular
308constructor for the passive advection of tracers in a rapidly evolving
309flow field that necessitates frequent updates of the velocity fields.
310
311@section messages Messages
312
313The memory that is consumed during the construction process is reported.
314*/

455/**
456
457Single-phase transport in a non-divergent flow. The method is either
458first- or second-order accurate depending on the boolean flag that
459was set when the 'ExplicitNodeCenteredFiniteVolumeTransport' object was constructed.
460
461@section arguments Input Arguments
462
463The method acts on the supplied Model object and advects the
464transport variable in the current velocity field for the time interval
465that the user specifies as second method argument.
466
467@return The advected transport variable is written back to the Model
468object.
469
470@section implementation Implementation
471
472The CFL_FACTOR is a multiplier that represents the maximum factor by
473which the diameter of the idealized spherical FV can be multiplied
474while the transport scheme is stable.
475
476@section messages Messages
477
478For each completed advection increment the method writes a dot on the
479screen as a progress monitor.
480
481@todo (3) Needs timestep reduction and DIRICHLET inflow condition
482
483*/
484template<uint32_t dim,template<uint32_t> class STP>
485double ExplicitNodeCenteredFiniteVolumeTransport<dim,STP>::AdvectVariable( double time_interval,
486 double cfl_multiplication_factor,
487 bool apply_flux_balance_correction,
488 bool update_pore_volumes )
489 {
490 this->gref_.RenumberNodes();
491
492 // 1. update the sector volumes and FVPOREVOL if so required (as in heat transport for instance)
493 // ---------------------------------------------------------------------------------------------
494 if ( update_pore_volumes ) {
495 const bool multiply_with_thickness_attribute = (this->thi_key_ != csmp::Index() ) ? true : false;
496 this->InitializeSectorPoreVolumeData( multiply_with_thickness_attribute );
497 this->InitializeArraysForFirstOrderMethod();
498 }
499
500 const double courant_increment( this->AnisotropicCourantIncrement() );
501
502 if ( cfl_multiplication_factor > 0.5 ) {
503 if (this->Verbose())
504 {
505 std::cout <<"\nExplicitNodeCenteredFiniteVolumeTransport<"<< dim <<">::AdvectVariable: ";
506 std::cout <<" In explicit mode, CFL multiplication factor must be less or equal to one(1/2). resetting..."<< std::endl;
507 }
508 cfl_multiplication_factor = 0.5;
509 }
510 if ( !apply_flux_balance_correction ) {
511 if (this->Verbose())
512 {
513 std::cout <<"\nExplicitNodeCenteredFiniteVolumeTransport<"<< dim <<">::AdvectVariable: ";
514 std::cout <<" Flux balance correction is applied automatically."<< std::endl;
515 }
516 }
517
518 // 2. compute the CFL condition to identify value for overstepping
519 // --------------------------------------------------------------
520 double time(0.), time_increment = std::min( courant_increment * cfl_multiplication_factor, time_interval );
521 bool output_result_range(false);
522 bool finish(false);
523
524 // 3. compute solution
525 // -------------------
526 if (this->Verbose()) std::cout <<"\n\n\nExplicitNodeCenteredFiniteVolumeTransport<"<< dim;
527 if (this->Verbose()) std::cout <<">::AdvectVariable: Advecting transport variable";
528 while ( time <= time_interval and !finish )
529 {
530 if ( (time_interval - time) <= time_increment ) {
531 time_increment = time_interval - time;
532 finish = true;
533 if (this->Verbose())
534 output_result_range = true;
535 }
536
537 if ( !this->SecondOrderInSpace() )
538 if ( this->diff_key_ != csmp::Index() )
539 // explicit 1st-order solution of advection-diffusion equation
540 AdvectAndDiffuseVariable1stOrder( time_increment, output_result_range );
541 else
542 {
543 // explicit 1st-order solution of advection equation
544 AdvectVariable1stOrder( time_increment, output_result_range );
545 }
546
547 else {
548 // explicit 2nd-order solution
549 if ( this->diff_key_ != csmp::Index() )
550 // explicit 2nd-order solution of advection-diffusion equation
551 AdvectAndDiffuseVariable2ndOrder( time_increment, output_result_range );
552 else
553 // explicit 2nd-order solution of advection equation
554 AdvectVariable2ndOrder( time_increment, output_result_range );
555 }
556
557 time += time_increment;
558 }
559
560 return courant_increment;
561
562 } // end AdvectVariable

636/**
637
638Explicit first-order advection algorithm of a passive conservative tracer.
639AdvectVariableFirstOrder() uses the upstream
640values of the advected variable to compose the solution in the result
641vector<double> managed by the ExplicitFiniteVolumeAlgorithm which performs
642a range check and writes the RESULT back to the Model.
643
644@section arguments Input Arguments
645
646Reference to the current model and the ExplicitFiniteVolumeAlgorithm as
647well as the time_increment for the transport step. This increment must
648fulfill the CFL criterion.
649
650@section implementation Implementation
651
652The method uses the ExplicitFiniteVolumeProcessor object in the
653accumulation of the finite-volume stencils, when it loops over the
654elements.
655
656@section application Application
657
658Since it costs almost the same to compute the second-order accurate
659explicit solution, there is not much rational to use this method.
660
661*/
662template<uint32_t dim,template<uint32_t> class STP>
663void ExplicitNodeCenteredFiniteVolumeTransport<dim,STP>::AdvectVariable1stOrder(
664 double time_increment,
665 bool output_result_range )
666{
667 for ( uint32_t ncom{0u}; ncom< this->var_ncomponents_; ncom++){
668 if ( this->Verbose() ) std::cout<<" Advecting component (ENCFVT): "<< ncom <<std::endl;

869/**
870
871Computes the values of the transported variable at the new time-level
872(passive advection case). Fluid sources or sinks as well as in or out-
873fluxes at Model or region boundaries as well as poroelastic sources
874are also taken care off by consideration of FLUX_BALANCE vector.
875
876@section arguments Input Arguments
877
878The method needs access to the current transport model and two vectors
879which store the pore volume of each finite volume cell and the flux
880balance of that cell, respectively. The method further requires a
881csmp::Index accessor to the transport variable in order to read
882current nodal values. Also, the current time-increment for
883the advection step needs to be specified in order to compose the
884solution. This time increment must satisfy the CFL condition, because
885this is an explicit transport scheme.
886
887@section implementation Implementation
888
889
890@section application Application
891
892For the passive advection of tracers.
893*/
894template<uint32_t dim,template<uint32_t> class STP>
895void ExplicitNodeCenteredFiniteVolumeTransport<dim,STP>::ComposeSolution( double time_interval, uint32_t var_comp_nr )
896{
897 if (this->adv1_key_.type == SCALAR){
898 for ( size_t nidx=0U; nidx<this->gref_.Nodes(); nidx++ )
899 {
900 // reading the transported variable value
901 double solution = this->gref_.N(nidx)->Read( this->adv1_key_ );
902 // adding potential (volumetric) source or sink terms due to a divergence of the flow (+ dt sum_j^e 1/3 V_e q_j)
903 if ( this->FLUX_BALANCE[nidx] != static_cast<double>(0.) )
904 RESULT[nidx] += solution * -this->FLUX_BALANCE[nidx];
905 // subtracting the flux time-interval product
906 RESULT[nidx] = solution - (time_interval / this->FVPOREVOL[nidx]) * RESULT[nidx];
907 // adding externally assigned source or sink terms
908 RESULT[nidx] += time_interval * this->gref_.N(nidx)->Read( this->src_key_ );
909
910 }
911 }
912 else if (this->adv1_key_.type == ARRAY){
913 ArrayVariable av;
914 if (this->src_key_.type == SCALAR)
915 {
916 for ( size_t nidx=0U; nidx<this->gref_.Nodes(); nidx++ )
917 {
918 // reading the transported variable value
919 this->gref_.N(nidx)->Read( this->adv1_key_ ,av);
920 double solution = av(var_comp_nr);
921 // adding potential (volumetric) source or sink terms due to a divergence of the flow (+ dt sum_j^e 1/3 V_e q_j)
922 if ( this->FLUX_BALANCE[nidx] != static_cast<double>(0.) )
923 RESULT[nidx] += solution * -this->FLUX_BALANCE[nidx];
924 // subtracting the flux time-interval product
925 RESULT[nidx] = solution - (time_interval / this->FVPOREVOL[nidx]) * RESULT[nidx];
926 // adding externally assigned source or sink terms
927 RESULT[nidx] += time_interval * this->gref_.N(nidx)->Read( this->src_key_ );
928 }
929 }
930 else if (this->src_key_.type == ARRAY)
931 {
932 ArrayVariable src_av;
933 double source;
934 for ( size_t nidx=0U; nidx<this->gref_.Nodes(); nidx++ )
935 {
936 // reading the transported variable value
937 this->gref_.N(nidx)->Read( this->adv1_key_ ,av);
938 double solution = av(var_comp_nr);
939 this->gref_.N(nidx)->Read( this->src_key_ , src_av);
940 source = src_av[var_comp_nr];
941 // adding potential (volumetric) source or sink terms due to a divergence of the flow (+ dt sum_j^e 1/3 V_e q_j)
942 if ( this->FLUX_BALANCE[nidx] != static_cast<double>(0.) )
943 RESULT[nidx] += solution * -this->FLUX_BALANCE[nidx];
944 // subtracting the flux time-interval product
945 RESULT[nidx] = solution - (time_interval / this->FVPOREVOL[nidx]) * RESULT[nidx];
946 // adding externally assigned source or sink terms
947 RESULT[nidx] += time_interval * source;
948 }
949 }
950 else
951 {
952 std::cout <<"ExplicitNodeCenteredFiniteVolumeTransport<dim>::ComposeSolution(): source variable type not implemented"<< std::endl;
953 }
954 }
955 else if (this->adv1_key_.type == FLAGGEDARRAY){
956 FlaggedArrayVariable fav;
957 for ( size_t nidx=0U; nidx<this->gref_.Nodes(); nidx++ )
958 {
959 // reading the transported variable value
960 this->gref_.N(nidx)->Read( this->adv1_key_ ,fav);
961 double solution = fav(var_comp_nr);
962 // adding potential (volumetric) source or sink terms due to a divergence of the flow (+ dt sum_j^e 1/3 V_e q_j)
963 if ( this->FLUX_BALANCE[nidx] != static_cast<double>(0.) )
964 RESULT[nidx] += solution * -this->FLUX_BALANCE[nidx];
965 // subtracting the flux time-interval product
966 RESULT[nidx] = solution - (time_interval / this->FVPOREVOL[nidx]) * RESULT[nidx];
967 // adding externally assigned source or sink terms
968 RESULT[nidx] += time_interval * this->gref_.N(nidx)->Read( this->src_key_ );
969

975/**
976 Accumulates facet fluxes (volume * saturation) coming into the control volumes into the result vector.
977*/
978template<uint32_t dim,template<uint32_t> class STP>
979void ExplicitNodeCenteredFiniteVolumeTransport<dim,STP>::AccumulateFluxUpwindProducts()
980{
981 // for all finite-volume facets
982 for ( uint32_t i{0u}; i<this->gref_.E(stencil_.eidx_)->FV()->Facets(); i++ )
983 {
984 // identifying the finite volumes to which the flux will be distributed
985 this->gref_.E(stencil_.eidx_)->FV()->FacetEdgeNodes( i, stencil_.inside_node_, stencil_.outside_node_ );
986
987 // for the "inside" node
988 if ( stencil_.facet_flux_[i] < 0. ) {
989 // 1. fluxes coming into the sector (fluxes = negative since normals are pointing outward) are added
990 // (outside node = upstream)
991 // -------------------------------------------------------------------------------------------------
992 RESULT[ this->gref_.E(stencil_.eidx_)->N(stencil_.inside_node_)->Idx() ] +=
993 stencil_.facet_flux_[i] * stencil_.psi1_[stencil_.outside_node_];
994 // 2. outgoing fluxes are subtracted
995 // ---------------------------------
996 RESULT[ this->gref_.E(stencil_.eidx_)->N(stencil_.outside_node_)->Idx() ] -=
997 stencil_.facet_flux_[i] * stencil_.psi1_[stencil_.outside_node_];
998 }
999 else {
1000 RESULT[ this->gref_.E(stencil_.eidx_)->N(stencil_.inside_node_)->Idx() ] +=
1001 stencil_.facet_flux_[i] * stencil_.psi1_[stencil_.inside_node_]; // out
1002 RESULT[ this->gref_.E(stencil_.eidx_)->N(stencil_.outside_node_)->Idx() ] -=
1003 stencil_.facet_flux_[i] * stencil_.psi1_[stencil_.inside_node_];
1004 }
1005 }
1006
1007} // end AccumulateFluxUpwindProducts
