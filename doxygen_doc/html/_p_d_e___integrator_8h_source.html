25@brief Accumulator and integrator for FEM or FVM-derived integral forms of PDEs
26and their solution by solving linear sets of linear algebraic equations (system Ax=b).
27Applicable to CSMP++ Model objects or their subregions.
28
29@author S.K. Matthai
30@author Stephen G. Roberts
31@author various extra contributions (Adrian Burri, Julian Mindel, Kho Luat Tran).
32@date 1997
33@date replaced by merge of PDE_Integrator 1/4/_22
34@date working toward a rigorous test of the functionality and better user feedback
35
36@section motivation Motivation
37
38To encapsulate the integration / numerical solution of
39partial-differential equations (PDE). This
40process entails
41
42(0) the creation of a sparsity pattern
43(1) the assembly of a sparse solution matrix, G, using integral contributions from finite elements or finite volumes,
44(2) the assembly of a right-hand vector with essential and initial conditions; before, Dirichlet conditions are eliminated.
45(3) Inversion of the matrix equation Ax=b to find the solution vector x.
46(4) Mapping the results from the result vector 'x' back onto the mesh, performing range checks.
47
48
49@section design Design
50
51The 'strategy' design pattern is used to separate the PDE operator / integrator implementation from the
52the type of finite element(s) or FV's used and the solution method chosen.
53As a consequence, the same PDE operator objects and solution methods can
54be used for a range of computational cell types with
55different node numbers and so forth.
56The Bridge pattern is used to decouple specific cell types and interpolation orders from the
57way the contributions from the finite elements are integrated. These implementations
58are found in collections of subclasses of the MathOperatorLHS and MathOperatorRHS,
59which are grouped together in specific PDE operator libraries.
60These are further subdivided into ones for analytic and others for numeric integration.
61
62The PDE_Integrator class is a base class from which specific PDE_Integrator subclasses can
63be inherited. These subclasses are found in the pde_integrators directory in the source.
64Subclasses are implemented to support nonlinear iteration loops
65and more user-friendly high-level forms of integrators like the SteadyStateDiffusor.
66
67
68@section applicability Applicability
69
70PDE_Integrator supports the solution of elliptic, parabolic and even hyperbolic PDEs in 2D and 3D .
71These computations can be targeted on the entire Model, Regions thereof and Boundary objects..
72
73
74@section participant Participants
75
76Each PDE_Integrator contains maps of pointers to left and righthand operators
77that are inherited from the MathOperatorLHS and MathOperatorRHS base
78classes. Other variables set the state of the algorithm, the time_increment
79in transient calculations and so forth.
80
81To solve the system of equations, the PDE_Integrator uses a Solver object.
82Different solvers can be configured, applied and managed via the Strategy pattern
83as described in the users guide.
84
85
86@section collaborations Collaborations
87
88PDE_Integrator interact with Model, Region, Boundary and SplitBoundary objects.
89It queries these objects for the data needed to setup the solution matrices and vectors.
90It also uses them to managed evolving boundary conditions, including ones
91needed to dynamically couple domains together.
92
93PDE_Integrator also collaborates with the MeshManager and the
94PropertyDatabase to gain access to variables and finite elements
95(Element class instances).
96
97PDE_Integrator obtains the finite-element contributions from the Element class
98that in turn has access to specific finite-element functionality via its FE policy.
99The interior workings of this remain hidden behind the interface of the specific element that is assembled.
100This is implemented as based on a 'bridge' pattern.
101
102
103@section consequences Consequences
104
105The design as a full-function base class implies that to create a PDE operator subclass one only has to
106overwrite those methods that one wants to modify.
107Other code does not need to be
108modified. To create additional PDE operators, inherit these from MathOperatorLHS or
109MathOperatorRHS.
110
111
112@section implementation Implementation
113
114The PDE_Integrator is a stand-alone object, which is passed to the Model or applied
115to one of its regions or boundaries with the IntegrateOver() method.
116The interaction with the Model follows a visitor-like pattern. The Model
117passes the PDE_Integrator on to a region to which its application has been restricted.
118Inside the Model, the following steps take place when a
119PDE_Integrator is applied by calling Model::Apply():
120
121To start with, the Model checks whether the PDE_Integrator must be handed down to
122a specific region, boundary or split boundary. Then the PDE_Integrator builds or updates its
123vectors and matrices so that they can store a sufficient number of entries:
124
125@code
126PDE_Integrator::EstablishMatrixSetup( mesh, phys_vars );
127@endcode
128
129Now the PDE_Integrator accumulates the contributions to the global solution
130matrix seqentially:
131
132@code
133PDE_Integrator::Accumulate ( mesh, property_collection );
134@endcode
135
136If the computation is a transient one, initial conditions are added into
137the righthand vector:
138
139@code
140PDE_Integrator::AssignInitialConditions( mesh, property_collection );
141@endcode
142
143Then, the boundary conditions are applied to the lefthand and righthand
144side:
145
146@code
147PDE_Integrator::AssignEssentialConditions( mesh, property_collection );
148Here an elimination is performed, retaining, if so, the symmetric shape of the solution matrix.
149@endcode
150
151If the computation is a transient one, and the time-stepping solution method is Backward
152Euler implicit, then righthand-side source terms (typically fluid
153source or other rates) are added to to the righthand vector after initial conditions were multiplied into it.
154For such integrals LateAccumulate needs to be specified.
155
156@code
157PDE_Integrator::LateAccumulate( mesh, property_collection );
158@endcode
159
160Now the solver is invoked to solve the ensuing linear algebraic system LHS * x = RHS.
161
162@code
163PDE_Integrator::Solve();
164@endcode
165
166The results from the computation are mapped back into property storage:
167
168@code
169PDE_Integrator::OutputResults( mesh, property_collection );
170@endcode
171
172and post-processing operations are applied:
173
174@code
175PDE_Integrator::PostProcess( mesh, property_collection );
176@endcode
177
178Post-processing may be, for instance, the computation of flow velocities
179from computed fluid-pressure gradients and permeability values.
180
181Important also is the mapping from global node ID numbers to entry
182positions in the global solution matrix troughout the solution process:
183In the simplest case, of a single degree-of-freedom per node and a global computation, the
184mapping is:
185
186G(n,n), rh(n) -> n = node-ID-1
187
188For vector variables:
189
190G(n,n), rh(n) -> n = (node-ID-1) * dimensions + j
191
192where j is the index variable for the spatial dimensions x, y, z.
193
194For tensor variables:
195
196G(n,n), rh(n) -> n = (node-ID-1) * dimensions^2 i*dimensions + j
197
198where i, j are the index variables corresponding to the rows and
199column indices of the tensor variable with the i_max = j_max =
200spatial dimensions.
201
202In the case of Region computations, an instance of the class
203IndexMapper transforms the global node ID numbers into the scaled
204ID numbers 1...n-nodes in group. Subsequently, the same transformations
205are applied for vector and tensor variables.
206
207
208@section examples Application Examples
209
210The simple most computation with an PDE_Integrator is a 3D steady-state
211computation of fluid pressure. This involves the definition and
212instantiation of some PDE operators as first step:
213
214@code
215 // compute steady-state fluid pressure from [K]{p} = {q}
216 PDE_Integrator<2U> fluid_pressure;
217
218 NumIntegral_dNT_op_dN_dV<2U> conductance( example_model.Database(), "conductivity", "fluid pressure", "fluid pressure" );
219 NumIntegral_NT_op_N_dV<2U> source( example_model.Database(), "fluid volume source", "fluid pressure" );
220 VelocityAndVolumeFlux<2U> velo( example_model, "conductivity", "porosity", "fluid pressure", true );
221
222 fluid_pressure.Add( &conductance );
223 fluid_pressure.Add( &source );
224 fluid_pressure.AddPostProcess( &velo );
225 example_model.Apply( fluid_pressure );
226@endcode
227
228
229A more advanced calculation of displacements, strains and stresses is
230done in the following example:
231
232@code
233 PDE_Integrator<2U> deformation;
234 if ( restricted_to_rock ) deformation.RestrictApplicationTo("rock");
235
236 PT_op<2U> bforces( p_ref, "force", "displacement" );
237 NumIntegral_BT_D_B_dV<2U> stiffness( p_ref, "Young's modulus", "Poisson's ratio", "displacement", "displacement");
238 if ( with_plane_stress ) stiffness.PlaneStress();
239 NumIntegral_PT_op_dS<2U> bstresses( p_ref, "Neumann stress", "displacement" );
240 NumIntegral_PT_op_dV<2U> bodyforce( p_ref, "gravity force", "displacement");
241 NumIntegral_BT_D_op_dV<2U> volstrain( p_ref, "dilatation", "Young's modulus", "Poisson's ratio", "displacement");
242 NumIntegral_BT_op_dV<2U> porepressure( p_ref, "fluid pressure", "displacement");
243
244 deformation.Add( &stiffness );
245 deformation.Add( &bforces ); // must always be there so that Dirichlet conditions are accumulated
246 if ( with_boundary_stresses ) deformation.Add( &bstresses );
247 if ( with_body_forces ) deformation.Add( &bodyforce );
248 if ( with_volume_strains ) deformation.Add( &volstrain );
249 if ( with_pore_pressure ) deformation.Add( &porepressure );
250
251 StressesAndStrains<2U> postpro( example_model, "Young's modulus",
252 "Poisson's ratio", "displacement", true, true );
253
254 if ( with_plane_stress ) postpro.PlaneStress();
255 deformation.AddPostProcess( &postpro );
256
257 example_model.Apply( deformation );
258@endcode
