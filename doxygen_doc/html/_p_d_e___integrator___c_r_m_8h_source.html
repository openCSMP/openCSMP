26@brief Accumulator and integrator for FEM or FVM-derived integral forms of PDEs
27and their solution in the form of linear algebraic sets of equations (system Ax=b).
28Applicable to CSMP++ Model objects or their subregions.
29
30@author S.K. Matthai
31@author Stephen G. Roberts
32@author various extra constributions (Adrian Burri, Julian Mindel, Kho Luat Tran).
33@date 1997
34@date replaced by merge of PDE_Integrator 1/4/22
35
36@section motivation Motivation
37
38To encapsulate the integration and numerical solution of
39partial-differential equations (PDE) in their integral form. This
40process entails (1) the assembly of a sparse matrix with the contributions
41from finite elements or finite volumes, (2) the assembly of a right-hand vector with
42essential and initial conditions; elimination of Dirichlet constraints.
43(3) Inversion of the matrix equation Ax=b to find the solution vector x.
44The dependent physical variable(s) stored in
45the solution vector are updated on the mesh.
46
47
48@section design Design Intent
49
50The intent of using a 'strategy' pattern for the
51design was to separate the PDE operator / integrator implementation from the
52the type of finite element(s) or FV's used and the solution method chosen.
53As a consequence, the same PDE operator objects and solution methods can
54be used for a range of computational cell types with
55different node numbers and so forth.
56
57The PDE_Integrator class is a base class from which specific PDE_Integrator subclasses can
58be inherited to test improvements of its functionality.
59
60
61@section applicability Applicability
62
63PDE_Integrator objects can be used to carry out any 2D and 3D computation which
64are possible with CSMP++. These computations may either appy to entire
65Model objects or to Regions which form subsets thereof.
66
67
68@section participant Participants
69
70Each PDE_Integrator contains maps of pointers to left and righthand operators
71that are inherited from the MathOperatorLHS and MathOperatorRHS base
72classes. Other variables set the state of the algorithm, the time_increment
73in transient calculations and so forth.
74
75PDE_Integrator also contains or connects to a Solver object which inverts the sparse solution matrix.
76
77
78
79@section collaborations Collaborations
80
81PDE_Integrator interact with Model, Region, Boundary and SplitBoundary objects.
82It queries these objects for the data needed to setup the solution matrices and vectors.
83
84PDE_Integrator also collaborates with the MeshManager and the
85PropertyDatabase to gain access to variables and finite elements
86(Element class instances).
87
88PDE_Integrator obtains the finite-element contributions from the Element class
89that in turn accesses the specific finite-element type which appears hidden
90behind the specific element that is assembled.
91This is implemented as a 'bridge' pattern.
92
93
94@section consequences Consequences
95
96The design as a full-function base class implies that to create a PDE operator subclass one only has to
97overwrite those methods that one wants to modify.
98Other code does not need to be
99modified. To create additional PDE operators, inherit these from MathOperatorLHS or
100MathOperatorRHS.
101
102
103@section implementation Implementation
104
105The PDE_Integrator is a stand-alone object, which is passed to the Model.
106The interaction with the Model follows a visitor like pattern. The Model
107passes the PDE_Integrator on to a region to which its application has been restricted.
108Inside the Model, the following steps take place when a
109PDE_Integrator is applied by calling Model::Apply():
110
111To start with, the Model checks whether the PDE_Integrator must be handed down to
112a specific region, boundary or split boundary. Then the PDE_Integrator builds or updates its
113vectors and matrices so that they can store a sufficient number of entries:
114
115@code
116PDE_Integrator::EstablishMatrixSetup( mesh, phys_vars );
117@endcode
118
119Now the PDE_Integrator accumulates the contributions to the global solution
120matrices seqentially:
121
122@code
123PDE_Integrator::Accumulate ( mesh, property_collection );
124@endcode
125
126If the computation is a transient one, initial conditions are added into
127the righthand vector:
128
129@code
130PDE_Integrator::AssignInitialConditions( mesh, property_collection );
131@endcode
132
133Then, the boundary conditions are applied to the lefthand and righthand
134side:
135
136@code
137PDE_Integrator::AssignEssentialConditions( mesh, property_collection );
138Here an elimination is performed, retaining, if so, the symmetric shape of the solution matrix.
139@endcode
140
141If the computation is a transient one, and the solution method is Backward
142Euler implicit timestepping, righthand-side source terms (typically fluid
143source or other rates) are now multiplied with the time increment and added
144to the righthand vector.
145
146@code
147PDE_Integrator::LateAccumulate( mesh, property_collection );
148@endcode
149
150Now the solver is invoked to invert the solution matrix:
151
152@code
153PDE_Integrator::Solve();
154@endcode
155
156The results from the computation are mapped back into property storage:
157
158@code
159PDE_Integrator::OutputResults( mesh, property_collection );
160@endcode
161
162and post-processing operations are applied:
163
164@code
165PDE_Integrator::PostProcess( mesh, property_collection );
166@endcode
167
168Post-processing may be for instance, the computation of flow velocities
169from computed fluid-pressure gradients and permeability values.
170
171Important is also the mapping from global node ID numbers to entry
172positions in the global solution matrix: In the simplemost case, of
173a single degree-of-freedom per node and a global computation, the
174mapping is:
175
176G(n,n), rh(n) -> n = node-ID-1
177
178
179For vector variables:
180
181G(n,n), rh(n) -> n = (node-ID-1) * dimensions + j
182
183where j is the index variable for the spatial dimensions x, y, z.
184
185For tensor variables:
186
187G(n,n), rh(n) -> n = (node-ID-1) * dimensions^2 i*dimensions + j
188
189where i, j are the index variables corresponding to the rows and
190column indices of the tensor variable with the i_max = j_max =
191spatial dimensions.
192
193In the case of Region computations, an instance of the class
194IndexMapper transforms the global node ID numbers into the scaled
195ID numbers 1...n-nodes in group. Subsequently, the same transformations
196are applied for vector and tensor variables.
197
198
199@section examples Application Examples
200
201The simple most computation with an PDE_Integrator is a 3D steady-state
202computation of fluid pressure. This involves the definition and
203instantiation of some PDE operators as first step:
204
205@code
206 // compute steady-state fluid pressure from [K]{p} = {q}
207 PDE_Integrator<2U> fluid_pressure;
208
209 NumIntegral_dNT_op_dN_dV<2U> conductance( example_model.Database(), "conductivity", "fluid pressure", "fluid pressure" );
210 NumIntegral_NT_op_N_dV<2U> source( example_model.Database(), "fluid volume source", "fluid pressure" );
211 VelocityAndVolumeFlux<2U> velo( example_model, "conductivity", "porosity", "fluid pressure", true );
212
213 fluid_pressure.Add( &conductance );
214 fluid_pressure.Add( &source );
215 fluid_pressure.AddPostProcess( &velo );
216 example_model.Apply( fluid_pressure );
217@endcode
218
219
220A more advanced calculation of displacements, strains and stresses is
221done in the following example:
222
223@code
224 PDE_Integrator<2U> deformation;
225 if ( restricted_to_rock ) deformation.RestrictApplicationTo("rock");
226
227 PT_op<2U> bforces( p_ref, "force", "displacement" );
228 NumIntegral_BT_D_B_dV<2U> stiffness( p_ref, "Young's modulus", "Poisson's ratio", "displacement", "displacement");
229 if ( with_plane_stress ) stiffness.PlaneStress();
230 NumIntegral_PT_op_dS<2U> bstresses( p_ref, "Neumann stress", "displacement" );
231 NumIntegral_PT_op_dV<2U> bodyforce( p_ref, "gravity force", "displacement");
232 NumIntegral_BT_D_op_dV<2U> volstrain( p_ref, "dilatation", "Young's modulus", "Poisson's ratio", "displacement");
233 NumIntegral_BT_op_dV<2U> porepressure( p_ref, "fluid pressure", "displacement");
234
235 deformation.Add( &stiffness );
236 deformation.Add( &bforces ); // must always be there so that Dirichlet conditions are accumulated
237 if ( with_boundary_stresses ) deformation.Add( &bstresses );
238 if ( with_body_forces ) deformation.Add( &bodyforce );
239 if ( with_volume_strains ) deformation.Add( &volstrain );
240 if ( with_pore_pressure ) deformation.Add( &porepressure );
241
242 StressesAndStrains<2U> postpro( example_model, "Young's modulus",
243 "Poisson's ratio", "displacement", true, true );
244
245 if ( with_plane_stress ) postpro.PlaneStress();
246 deformation.AddPostProcess( &postpro );
247
248 example_model.Apply( deformation );
249@endcode
