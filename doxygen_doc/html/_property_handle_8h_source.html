16@brief PropertyHandle - a global accessor and mutator of distributed data
17
18@author S.K. Matthaei
19@author Stephen G. Roberts
20@date 1999
21
22
23@section motivation Motivation
24
25Especially for test computations, one would like write arithmetic
26expressions which apply to distributed physical variables. To make
27these expressions concise it is useful to replace lengthy variable
28names by a notation of choice, for instance, to define a variation
29of porosity with depth:
30
31phi = phi - 1 / z^2
32
33Finally, there is a need to create variables for such mathematical
34expressions at runtime.
35
36
37@section design Design Intent
38
39The PropertyHandle was designed following the motivation from above, but
40also by using the existing Operand classs as a model. Thus, an PropertyHandle shares
41many of the Operand interfaces, but as a difference, it will currently
42apply to the associated variable on all the elements, nodes, or constraint
43points of a mesh, depending on where the PropertyHandle variable is placed.
44
45The desired capability of writing arithmetic expressions is implemented
46via C++ operator overloading. Notably, there is no assignment operator for
47operands to operands, since the expected result of a C++ assignment
48would imply a complete overwriting of the lefthand physical variable with
49the one on the right of the assignment operator.
50
51Self-assignment is provided to write expressions which are efficient,
52since they do not require the creation of temporary variables. Thus, the
53expression
54
55phi = phi - 1 / z^2
56
57can be replaced by
58
59phi -= 1 / z^2
60
61which avoids the creation of a temporary variable for the righthand side
62which would subsequently be assigned to 'phi' on the left.
63
64
65@section applicability Applicability
66
67PropertyHandles can be applied anywhere in a main program or a high-level
68class object or function which has access to the CSMP library. To create
69a PropertyHandle its constructor takes arguments which allow it to associate
70itself with an existing variable in the Model or to request a new
71Model variable which will be globally known until the PropertyHandle is
72destructed again. If a new variable is created, it will be destroyed when
73the destructor of the PropertyHandle is called.
74
75
76@section participants Participants
77
78The PropertyHandle has references to the Mesh and Memory managers, and
79the PropertyDatabase and it stores the csmp::Index of the associated
80physical variable for rapid variable access.
81
82
83@section collaborations Collaborations
84
85The PropertyHandle collaborates with the Model and its contained
86managers in order to carry out its arithmetic operations.
87
88
89@section consequences Consequences
90
91PropertyHandles allow the user to add, subtract, multiply, and divide
92distributed physical variables among eachother, to assign values to
93them, or to add, subtract, multiply, and divide CSP basic variables to
94the distributed physical variables.
95
96
97@section implementation Implementation
98
99For clarity, the placement and type of the physical variables which
100are associated with PropertyHandles are used to impose restrictions on
101whether PropertyHandles can be used together in arithmetic expressions.
102Only if the placement and variable type is the same this can be
103done.
104
105The user is requested to make recommendations of how PropertyHandles can
106be made more flexibility while avoiding ambiguities of assigning
107variables of different type to one another.
108
109
110@section examples Application Examples
111
112Below the full source code for the porosity example from above is listed:
113
114@code
115// existing property using default arguments
116PropertyHandle phi( current_supergroup, "porosity", SCALAR, ELEMENT );
117phi = 0.4;
118
119// new property
120PropertyHandle z( current_supergroup, "depth", SCALAR, ELEMENT );
121
122// initialize the new property using an Interrelation subclass
123AssignDepthToProperty make_depth( reference_to_property_database );
124current_supergroup.Apply( make_depth );
125
126// desired arithmetic expression
127phi -= 1 / z^2;
128phi.OutMatlab();
129@endcode
130
131In this example, the existing scalar element variable 'porosity' is assigned
132to the PropertyHandle 'phi' and intialized to 40%. The construction of the
133PropertyHandle 'z' prompts the generation of a new variable "depth" as
134a scalar placed on the element and initialized to NAN (not a number).
135The interrelation AssignDepthToProperty assigns the z-coordinate of the
136element centers to the new variable 'depth'. Now the following arithmetic
137expression has the necessary input values and can be applied. The result
138is output to a text file in Matlab format.
139
140PropertyHandles also allow to create temporary variables, then apply
141standard mathematical operations on these, and subsequently output
142the results to a file for visualization. In the following example, the
143natural logarithm of the variable porosity is output to a textfile:
144
145@code
146PropertyHandle phi( current_supergroup, "porosity", SCALAR, ELEMENT );
147PropertyHandle log_phi( current_supergroup, "log porosity", SCALAR, ELEMENT );
148
149// assign the porosity to the new variable without direct assignment
150log_phi = 0.0;
151log_phi += phi;
152// logarithmitize the values
153
154log_phi.Log();
155log_phi.Out( logarithmitized_porosity );
156
157// delete the temporary variable
158log_phi.~PropertyHandle();
159@endcode
160
