19UnitTests and Test Driven Development increase confidence in the code you write and
20drastically reduce debugging needs. In an environment like CSMP that is not tested
21bottom up, a different approach to testing new classes may be chosen.
22Also for classes that act on a csmp::Model, the user might skip test
23driven development/unit testing due to the high effort required. This document tries
24to provide an approach to CSMP specific TDD.

37@section tests Unit Tests and Functional Tests
38
39@subsection general In general XP
40
41A Unit Test is designed to test the interface of a single class through proper pass/fail
42criteria. A Functional Test tests the result of class interactions within a bigger context.
43Hence, pass/fail criteria are more complex. This also includes performance test and the
44validation of applications in their whole.
45
46@subsection csmp Interpreted for CSMP
47
48To test classes that require a model to act on, multiple Unit Tests may be run within
49one test function and work with the same model. Classes are tested indepently from another,
50and the TestSuite will spot failures individually. To sum it up, we put multiple tests
51inside a single test function that establishes a model for all of them. This is
52done to reduce the effort that goes into creating a test.
53Functional Tests, or Test Cases, measure performance and compare results of complex applications.
54
55@section tdd Introduction to TDD
56
57Write your Unit Test first, let it fail(because there is no class yet, afterall) then
58implement your class piecewise to make the tests pass. Once the tests pass, improve your code.
59Benefits:
60- improves design
61 - think it through
62 - then implement
63- reduces amount of code
64 - by sticking to what you really planned to do
65 - by having code that does the job quickly
66 - and improve it when there's time
67- used together with SVN, often replaces debugger
68 - revert to revision that works, go form there
69- YOU CAN TRUST IN YOUR CODE AN SUBSEQUENT USE OF IT
70- IT IS TESTED(what's the alternative?)
71
72How it's done:
73-# Write your test
74-# See it fail
75-# Implement your code
76-# Make the test pass

80Basic Unit Test and TDD with CSMP's csmp::Test and csmp::TestSuite class.
81Available Macros:
82-_test( cond ) tests for logical statement
83-_fail( stri ) fails
84-_equal( arg1, arg2, tolerance ) tests if arguments equal within tolerance

86@code
87 // implementation follos
88 class Unit
89 {
90 public:
91 int foo1( int a ) { return a/a; }
92 int foo2( int a ) { return a*a; }
93 };

95 // this comes first(failing)
96 class UnitTest : public Test
97 {
98 public:
99 virtual void run() { _test( Unit().foo1( 5 ) == 1 );
100 _test( Unit().foo2( 5 ) > 5 ); }
101 };

117e.g. Interrelations.

119@code
120
121// global function to reload model from binary
122void resetModel( Model<DIM>* model )
123{
124 if( model != 0 )
125 delete model;
126 model = new ANSYS_Model3D( "small_prism_bin",
127 "CSMP-2phase-variables.txt" );

130class MultipleUnitTest : public Test
131{
132public:
133 virtual void run() {
134
135 // establishing a test model
136 Model<DIM>* model;
137 resetModel( model );
138
139
140 // getting indices to evaluate test criterion
141 const Region<dim>& rref = model->Region( "Model" );
142 Index porosityKey = model->Database().StorageKey( "porosity" );
143 Index frapKey = model->Database().StorageKey( "fracture aperture" );
144
145 // backing up property that will be manipulated
146 PropertyHandle<DIM>* cachePorosity = new PropertyHandle<DIM>( (*model), "cache porosity", SCALAR, ELEMENT );
147 Index cachePorosityKey = model->Database().StorageKey( "cache porosity" );
148 (*model).CopyReplace( "porosity", "cache porosity" );
149
150 // Applying an Interrelation to the model
151 FracturePorosityFromAperture<DIM> fracturePorosityInterrelation( (*model).Database() );
152 (*model).Apply( fracturePorosityInterrelation );
153
154 // Running a trivial test criterion
155 bool passed( true );
156 const std::vector<Element<DIM>*>::const_iterator elementsEnd = rref.CellsEnd();
157 for( std::vector<Element<DIM>*>::const_iterator it = rref.CellsBegin();
158 it != elementsEnd; ++it )
159 {
160 if( (*it)->Read( porosityKey ) != (*it)->Read( cachePorosityKey ) *
161 (*it)->Read( frapKey ) )
162 {
163 passed = false;
164 break;
165 }
166
167 // if we wish to test more than one interrelation within one loop, we do
168 // _equal( (*it)->Read( cacheValue1Key ), (*it)->Read( value1Key ) ), tolerance_ );
169 // _equal( (*it)->Read( cacheValue2Key ), (*it)->Read( value2Key ) ), tolerance_ );
170 // ....
171 // as long as the tests still qualify as independent
172 }
173
174 // evaluating test criterion
175 _test( passed );
176
177 // restoring model
178 (*model).CopyReplace( "cache porosity", "porosity" );
179 delete cachePorosity;
180
181 //...tests
182
183 // resetting model if required
184 resetModel( model );
185
186 //...tests
187
188
189 } // run
190
191};
192
193int main( int argc, char** argv)
194{
195 TestSuite s("TDD SUITE", &cout);
196
197 s.addTest( new MultipleUnitTest() );
198
199 s.run();
200 int failures = s.report();
201
202 return failures;
203 }
204@endcode
