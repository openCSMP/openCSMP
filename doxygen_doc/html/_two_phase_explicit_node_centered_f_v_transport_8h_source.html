111@section motivation Motivation
112
113The TwoPhaseExplicitNodeCenteredFVTransport module performs
114advection a single non-wetting phase in two-phase flow simulations.
115It is a CFL dependent transport scheme for arbitrary FE meshes including
116different FE types and mixes of volume and surface elements.
117
118The scheme is tolerant in that no specific boundary conditions
119need to be applied. The value of the advected variable at inflow
120boundaries is not modified and governs what gets transported into
121the model domain.
122
123@section applicability Applicability
124
125Use the explicit scheme if the transport velocity field is rapidly changing /
126invalidated by the transport itself. In this case the scheme is faster
127than the implicit scheme. The use of the latter will
128start to pay off at about CFL=20 or greater.
129
130Do not use this scheme when the CFL condition based transport increment
131leads global advection steps that are smaller than about 1/1,000 of the
132model length in the direction of the flow. In this case the computations
133would be prohibitively slow.
134
135@section structure Structure
136
137The explicit advection scheme consists out of the three modules which are
138documented in a power-point documentation in the documentation folder.
139
140TwoPhaseExplicitNodeCenteredFVTransport
141ExplicitStencilProcessor
142
143The user will only interact with the TwoPhaseExplicitNodeCenteredFVTransport module.
144The ExplicitStenProcessor class facilitates the generation of the
145finite-volume stencil contributions from each finite element, so that the accumulation
146can proceed on an element by element basis. No FV mesh needs to be stored.
147
148
149@section implementation Implementation
150
151Flux-balances are computed for all finite volumes including those
152which are located on the boundaries of the Region or Model to
153which the transport scheme is applied. They are compensated for also
154on all domain boundaries.
155
156
157@section examples Application Examples
158
159This is an example of how the second order accurate scheme is applied:
160
161@code
162
163TwoPhaseExplicitNodeCenteredFVTransport<1U,ExplicitStencilProcessor>( "Model",
164 reservoir_model,
165 "porosity",
166 "capillary diffusivity",
167 "saturation water", "saturation oil",
168 "velocity",
169 "nodal fluid volume source",
170 second_order_accurate );
171
172 cout <<"\n\nTransportPhase: Configuring TRANSPORT simulation: ";
173 if ( second_order ) cout <<" IMPES: SECOND ORDER SCHEME."<< endl;
174 else cout <<" IMPES: FIRST ORDER SCHEME."<< endl;
175 cout <<"\nThe grid Courant number is "<< explicit_advector.AnisotropicCourantIncrement( reservoir_model ) << endl;
176 cout <<"\nEnter advection time: ";
177 double time_interval;
178 cin >> time_interval;
179 cout <<"\n\tMeasuring the time required to solve the advection problem."<< endl;
180 clock_t ticks = clock();
181 explicit_advector.TransportPhase( relperm_model, time_interval );
182 ticks = clock() - ticks;
183 cout <<"\n\n\tCPU clock ticks used for advection step: "<< ticks << endl;
184
185@endcode
