191/**
192
193@class TwoPhaseImplicitNodeCenteredFVTransport TwoPhaseImplicitNodeCenteredFVTransport.h
194"generic_node_centered_finite_volumes/TwoPhaseImplicitNodeCenteredFVTransport.h"
195
196@author S.K. Matthaei
197@date 2002
198
199
200@section motivation Motivation
201
202The TwoPhaseImplicitNodeCenteredFVTransport module is provided to allow users
203to perform passive advection and advection of a single non-wetting
204phase in two-phase flow simulations. It represents the fastest but
205CFL dependent transport scheme for arbitrary FE meshes including
206different FE types and mixes of volume and surface elements.
207
208The scheme is also very tolerant in that no specific boundary conditions
209need to be applied. The value of the advected variable at inflow
210boundaries is not modified and governs what gets transported into
211the model domain.
212
213
214@section design Design Intent
215
216The scheme has been designed to capitalize on the new generic polytype
217CVFE technology that is part of CSMP.
218
219
220@section applicability Applicability
221
222Use the scheme if the transport velocity field is rapidly changing or
223invalidated by the transport itself. In this case the scheme is faster
224that the implicit scheme embodied in the FiniteVolumeTransport module
225which starts to pay off at about CFL=20 or greater.
226
227Do not use this scheme when the CFL condition based transport increment
228leads global advection steps that are smaller than about 1/1,000 of the
229model length in the direction of the flow. In this case the computations
230would be prohibitively slow.
231
232
233@section structure Structure
234
235The user will only interact with the TwoPhaseImplicitNodeCenteredFVTransport module,
236but the FiniteVolumeAlgorithm is used to manage the accumulation
237and output of the solution in each transport step, and the
238FiniteVolumeProcessor class facilitates the generation of the
239finite-volume stencils from each finite element, so that the accumulation
240can proceed on an element by element basis and no FV mesh needs to be
241stored.
242
243
244@section collaboration Collaboration
245
246The scheme collaborates with the finite elements of the current model.
247
248
249@section consequences Consequences
250
251This implementation of the scheme cannot be restricted to Regions, but
252always needs to be applied to the entire model, i.e. Model.
253
254Currently it also only works for 3D models. Surface computations can
255still be done if the mesh consists entirely of surface elements in
2563D space.
257
258*/
