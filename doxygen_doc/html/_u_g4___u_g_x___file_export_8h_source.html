28/**
29
30Export interface for writing text files in the .ugx format using XML for the formatting.
31Explanations of the UG4 output tags.
32
33Drawing on the information provided in 'file_io_ugx*' in conjunction with the GridWriterUGX class.
34Some enumerations in grid/grid_base_objects.h
35
36To assign properties to the grid, attachment traits are used.
37These are: vertex, edge, face and volume.
38
39@attention Design choices had to be made to crerate the additional edge and face data
40that UG4 needs for during the output:
41
42Importantly, CSMP models store edges and faces only if these are needed as lower-dimensional entities
43for computations (well and fracture modelling, assignment of boundary condtions etc.). In UG4 they are always
44needed and their numbering must be unique.
45
46The choice made for the implementation of this CSMP-UG4 interface is that those edges and faces that
47are present in the CSMP model are later identified in the edges and faces vectors created for UG.
48What is output is the "model domain" plus the faces (and interfaces) touching it.
49Their 'idx' is mapped that of the edge and faces created for UG.
50
51Region and Boundary output enlists all the nodes, edges and faces that belong to these,
52although UG4 only wants them to be listed once. Here, the feature in Promesh which eliminates
53excess edges and faces is relied upon.
54
55@attention properties are no associated with regions but communicated as node, edge, face and volume attachments.
56Since the CSMP model only contains property values for those elements, faces, interfaces and nodes
57present in there, no-data values are printed for all the other ones needed by UG.
58

107@section XML tags used
108
109The hierarchical XML tags above are getting processed here using the functionality in XML.
110Comments in XML files are inserted using <!-- text -->
111The tags suported here were defined by Andreas Vogel, and this is the correspondence list to CSMP types:
112
113grid -> mesh
114vertices -> nodes
115edges, triangles, quadrilaterals -> line elements, triangular elements, quadrilateral elements etc.
116subset = region or boundary
117subset_handler -> class without specific purpose yet. Only a single subset handler needs to be present.
118Its name is "defSH" (default subset handler)
119
120projection_handler for the transformation of coordinates to another systems
121
122vertex, edge, face, volume -> element type independent identifier of elements of a specific topologic dimensionality
123
124@attention the .ugx format requires lists for all the subentities of the actual finite elements in a mesh.
125These are listed using the implicit integer numbers of the nodes ( vertices). It follows, that a 3D models needs:
126
127<edges> unique pairs of nodes that define the edges of all elements in the model
128
129<triangles> the vertex ids (0..n-1) that define the faces of simplex elements
130<quadrilaterals> the faces of hexadral, prism, and pyramid elements
131
132Note that these numbers have to be repeated for each region and boundary of the mesh, using the same numbering implicit to their order.
133
134
135@section Storing the properties of a model
136
137Variables are stored as "attachments."
138
139
140@section Variable Types
141
142common_attachments.h defines the types of variables that can be associated with nodes, edges, faces and elements. These are spelled out also in`
143global_attachments.h -> attachment_info_traits -> distinguishing double, float, int, bool, vector1, vector2, vector3, vector4.
144
145Vectors and matrices are typedef'd in /common/math/ug_math_types.h
146
147matrix22, matrix33, matrix44
148
149All these types are referred to via strings in the output .ugx file.
150
151@attention UGX file only stores straight-sided elements with corner nodes only. Any refinement occurs inside of UG.
152This may include obtaining body-fitted representations of curves etc.
153
154@author SKM
155#date 3/12/2-23
156

162
163 /// filename without extension which will be appended
164 bool Write_UGX_FileASCII( const Model<dim>&, const std::string& file_name );
165
166 private:
167 UG4_UGX_FileExport() = delete;
168 UG4_UGX_FileExport( const UG4_UGX_FileExport& ) = delete;

170 /// Loops over the unique regions in the model to make a vector of the unique edges (node-iD pairs) in the model (corner nodes only)
171 size_t CollectEdges( const Model<dim>& );
172
173 /// creates two sorted vectors for triangular and quadrilateral elements, respectively
174 size_t CollectFaces( const Model<dim>& );
175
176 /// creates sorted vectors for tetra, hexa, prism, and pyramid elements
177 size_t CollectVolumes( const Model<dim>& );
178
179 // SUBSET mapping
180 /// Finds the ID numbers of the edges in the global edge vector inside of the region
181 size_t CollectEdgesInRegion( const Region<dim>&, std::vector<size_t>& region_edges ) const;
182 size_t CollectFacesInRegion( const Region<dim>&, std::vector<size_t>& region_faces ) const;
183 size_t CollectVolumesInRegion( const Region<dim>&, std::vector<size_t>& region_volumes ) const;
184
185 size_t CollectEdgesInBoundary( const Boundary<dim>&, std::vector<size_t>& region_edges ) const;
186 size_t CollectFacesInBoundary( const Boundary<dim>&, std::vector<size_t>& region_faces ) const;
187
188 // helpers
189 bool HasTriangles() const { return !tria_faces_.empty(); }
190 bool HasQuadrilaterals() const { return !quad_faces_.empty(); }
191 bool HasTetrahedra() const { return !tetra_volumes_.empty(); }
192 bool HasHexahedra() const { return !hexa_volumes_.empty(); }
193 bool HasPrisms() const { return !prism_volumes_.empty(); }
194 bool HasPyramids() const { return !pyra_volumes_.empty(); }
195
196 /// returns CSMP line element/face/interface idx if it exists or UNSPECIFIED if not
197 unsigned long EquivalentEdgeInCSMP( size_t ug_idx ) const;
198
199 /// returns CSMP line element/face/interface idx if it exists or UNSPECIFIED if not
200 unsigned long EquivalentFaceInCSMP( size_t ug_idx ) const;
201
202 /// using the node numbering in the region 'Model' the property values at the vertices are written out
203 void WriteVertexVariableValue( std::ofstream&, const csmp::Index&, const Region<dim>&, size_t ug_cell_idx, bool& print_whitespace ) const;
204
205 void WriteEdgeVariableValue( std::ofstream&, const csmp::Index&, const Region<dim>&, size_t ug_cell_idx, bool& print_whitespace ) const;
206 ///
207 void WriteFaceVariableValue( std::ofstream&, const csmp::Index&, const MeshManager<dim>&, size_t ug_cell_idx, bool& print_whitespace ) const;
208 ///
209 void WriteVolumeVariableValue( std::ofstream&, const csmp::Index&, const MeshManager<dim>&, size_t ug_cell_idx, bool& print_whitespace ) const;
210
211 // translation of CSMP variable types to UG variable types
212 std::string UG_VariableType( const csmp::Index& ) const;
213
214 // extra datasets needed for UGX output; note that the set of global node ids gets sorted!
215 // UG also does not require that nodes, edges, faces and volumes are listed in any particular numbering sense.
216 // Thus, sorting allows to use them as search keys.
217 // Note also that the UGX format only supports elements with linear shape functions, higher-order elements are created inside of UG
218 // global node ids, followed by element ID of edge
219 std::vector<std::pair<size_t,size_t>> edges_; ///< global edge end-node IDs for all edges in the model as needed by UG (n...total)
220 // csmp-idx, edge-#
221 std::map<size_t,size_t> csmp_edges_, csmp_edges_inverted_; ///< mapping between CSMP element/face IDs and edge number in UG
222
223 std::vector<std::pair<std::set<size_t>,std::array<size_t,3>>> tria_faces_; ///< triangle faces numbered continuously from 0..faces-1, second original node order
224 std::vector<std::pair<std::set<size_t>,std::array<size_t,4>>> quad_faces_;
225
226 std::vector<std::pair<std::set<size_t>,size_t>> tetra_volumes_, ///< volumes = tets + hexa + prism + pyra, numbered continuously
227 hexa_volumes_,
228 prism_volumes_,
229 pyra_volumes_; ///< volumetric elements present only in 3D models
230 // csmp-idx,ug-id
231 std::map<size_t,size_t> csmp_faces_, csmp_faces_inverted_; ///< mapping between CSMP element/face IDs and face-number in UG
232
233 std::vector<bool> edges_in_csmp_, faces_in_csmp_; ///< vectors that can be queried before a search of a CSMP object is carried out to see whether it exists at all
234
235 // printing of region=subset ids (0..n-1) which requires searching the edges, faces, and volumes vectors
236 bool with_region_edge_output_ = true;
237 bool with_region_face_output_ = true;
238 bool with_region_volume_output_ = true;
239
240 bool with_boundary_edge_output_ = true;
241 bool with_boundary_face_output_ = true;
242};
