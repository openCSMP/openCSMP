19@section motivation Motivation
20
21Mesh connectivity usually termed as VData typically consists of lists
22of (1) node and constraint-point coordinates (constraint points can be nodes
23between nodes but also integration points), (2) a listing of the nodes
24which belong to each element, and (3) a list of the neighbors of each
25element. If the element lies on the model boundary and there is no neighbor
26then entries in this list will be UNSPECIFIED. (4) A typical VData set
27also specifies which nodes lie at the model boundary and which property
28values apply to these nodes.
29
30The class VData brings all these datasets together into an object
31which holds the information to build this V-type mesh connectivity.
32
33@section applicability Applicability
34
35VData can be used as isolated object but it is also integrated into
36the VSet which also holds property data which are assigned to the
37mesh.
38
39@section structure Structure
40
41The VData object contains coordinate objects, deques of
42vectors to store the connectivity and maps to hold the boundary flags
43and boundary values.
44
45Detailed content:
46
47(double) px, py, pz[0..n-1] = coordinates of n nodes (= FE vertices)
48
49(int8_t) bflags[0..n-1] = negative numbers for nodes at boundary, see later
50
51(enum int8_t) pelmt[0..e-1] = CSMP_FEM_TYPE of e finite elements (1 entry only for single element-type mesh)
52
53(size_t) plist[0..e *[sum npe[e]]] = nodes making up each element
54
55(int64_t) pfverts[0..e *[sum fpe[e]]] = neighbor elements adjacent to the faces of each element
56
57For Face and InterFace objects, 'pfverts' also contains the indices of the higher-dimensional neighbor element.
58
59*/
