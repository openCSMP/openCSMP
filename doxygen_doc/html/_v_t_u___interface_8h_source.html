51/**
52 @brief Interface for the creation of XML files for the visualisation toolkit (VTK).
53
54 @author P. Lang
55 @date 2010
56
57 @attention still issues with nan values(when attempting to visualized uninitialized vars in paraview)
58
59 Interface for serial unstructured VTK XML files (.vtu).
60 The VTU file format is considered to be of greater flexibility
61 and to offer more options than the legacy format(VTK). The main
62 advantage of this interface lies in the fact that the connectivity
63 part is only build once for each region, and is reused in consecutive
64 outputs. This results in major speed increase during repetitive
65 outputs.
66
67 It is possible to output multiple variables to one file, the interface
68 automatically separates element placed vectors and tensors to another
69 file, since a different connectivity is required (point cloud output).
70
71 @section features Features
72 The key features of this interface are:
73 -Direct mapping from CSMP to VTK elements / nodes
74 -Linear and Quadratic elements
75 -Node and Element properties
76 -Caching of connectivity data for speed up in consecutive outputs
77 -Writing several property data into one file
78 -Output of 2D and 3D models
79
80 @section application Application Example
81
82 The methods of this interface resemble those of the VTK_Interface.
83 To instantiata a VTU_Interface, dimension and a reference to the
84 model has to be provided
85
86 In the simplest case, all you need is
87 @code
88 VTU_Interface<SPACE> vtu( model );
89 vtu.OutputDataToVTU( "BOX", "fluid pressure" );
90 vtu.OutputDataToVTU( "BOX", "fluid pressure", "FRACTURES" );
91 vtu.OutputDataToVTU( "BOX", "fluid pressure", "FRACTURES", model_time );
92 @endcode
93
94 For further details:
95
96 @code
97 // dimension, csmp::Model and an optional session/simulation title
98 VTU_Interface<3U> vtu( model, "Debug Session" );
99 @endcode
100
101 If you elect to output one variable only:
102
103 @code
104 // 'permeability' of entire model at time 0
105 // file will be named 'ModelPermeability0.vtu'
106 vtu.OutputDataToVTU( "ModelPermeability", "permeability" );
107
108 // as above, but for region 'FRACTURES'
109 // file will be named 'FRACTURES_Permeability1333.vtu' for model_time = 1333
110 vtu.OutputDataToVTU( "Permeability", "permeability", "FRACTURES", model_time );
111 @endcode
112
113 If you wish to output multiple properties:
114
115 @code
116 // create a list of the variables at the beginning
117 list<string> vtuVariables;
118 props.push_back( "fluid pressure" );
119 props.push_back( "total mobility" );
120 props.push_back( "saturation oil" );
121
122 //...
123
124 // to output all properties to single VTU file for entire model
125 // file will be named 'Simulation0.vtu'
126 vtu.OutputDataToVTU( "Simulation", vtuVariables );
127
128 // as above but for specific region
129 // file will be named 'FRACTURES_Simulation0.vtu' etc
130 vtu.OutputDataToVTU( "Simulation", vtuVariables, "FRACTURES" );
131
132 // as above but for specific region and model time
133 // file will be named 'FRACTURES_Simulation1333.vtu' etc
134 vtu.OutputDataToVTU( "Simulation", vtuVariables, "FRACTURES", model_time );
135 @endcode
136

138
139 csmp Elements are directly mapped to their vtk counterpart(no simplification
140 of geometry/transformation of nodes/element types)
141
142 @code
143 ISOPARAMETRIC_LINEAR_BAR
144 LINEAR_BAR
145 LINEAR_TRIANGLE3D
146 ISOPARAMETRIC_LINEAR_TRIANGLE
147 LINEAR_TRIANGLE
148 ISOPARAMETRIC_LINEAR_TETRAHEDRON
149 LINEAR_TETRAHEDRON
150 ISOPARAMETRIC_LINEAR_PYRAMID
151 ISOPARAMETRIC_LINEAR_PRISM
152 ISOPARAMETRIC_LINEAR_QUADRILATERAL
153 ISOPARAMETRIC_LINEAR_HEXAHEDRON
154 ISOPARAMETRIC_QUADRATIC_BAR
155 QUADRATIC_BAR
156 ISOPARAMETRIC_QUADRATIC_TRIANGLE

166 @section implementation Implementation
167
168 Requires 'VTK_Interface.h' for VTK element enumeration.
169
170 For the sake of user readability, binary output was postponed to a later
171 point in development, as was offset/appended data arrays.
172
173 Furthermore, Point locations are described by a single data array, holding their
174 x, y and z position(in this order). This approach also should increase readability
175 compared to the alternative of having 3 seperate DataArrays, each holding the x, y and
176 z coordinates for all points.
177
178 Instantiating creates the connectivity file that may be reused consequently.
179 Calling OutputToVTU opens a new file, writes Headers, Mesh and Data and closes
180 the file, leaving vtuFile_ == 0.
181
182 The node numbering convention of VTK is consistent with CSMP's for linear FEs, but
183 not so for quadratic ones.
184
185 Uses member function pointers for visitor like node/element loops when writing
186 data arrays.
187
188 Convention is that all outputs end with a new line each.
189
190 @todo (3) Fix tensor output( if dim == 2 )
191 @todo (3) Exceptions
192 @todo (3) Implement true/false checks in bool members
193 @todo (3) In insertConnectivityFile<dim> check whether insertion sucessfull
194 @todo (3) Update doc
195 @todo (3) think about bringing in mem alloc class to manage vtu files
196 @todo (3) Additional info in xml header(see legacy vtu interface)
197 @todo (3) Replace list by set as property container
198
199 @note minor refactoring by SKM.
200
201 @todo break class into smaller functional units and remove code bloat by duplication.
202 @todo simplify interfaces.
203
