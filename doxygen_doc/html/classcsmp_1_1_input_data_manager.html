Detailed Description

template<uint32_t dim>
class csmp::InputDataManager< dim >

input of parameter values from block-structured text file.

Author
S.K. Matthai
S. Geiger
S.G. Roberts
Date
2001

Motivation

To have an ASCII-file based interface to CSMP which allows to assign material properties and initial conditions to models and their subregions as identified by unique names (of groups).

Boundary and essential conditions should also be assignable via condition flags and this approach needs to work in 1-3D and both for box- and for freeform models.

Since many meshing tools do not allow to assign names to subregions of models / meshes, but subregions and model internal and external boundaries are identified by integer or floating point (material property) values, this interface should also provide the possibility to create named model subregions from property values and ranges. The only possible properties for this purpose inside of CSMP are element properties. This is because each subregion must at least consist of one finite element.

Design Intent

A simple design is achieved by dividing the input data into five different data blocks. The user decides which blocks to read, by setting boolean flag arguments to ConfigureFromFile():

Block 1 - to define named regions of elements with characteristic values of element properties.

Block 2 - to set default property values for the entire model. These can get overwritten in individual subregions by the values and flags supplied in the data blocks 3-5.

Block 3 - property values for model subregions. The user can determine whether these values are applied to the entire subregion (option=COMPLETE), its boundary (option=PERIMETER), or only the interior of the region (option=INTERIOR). The CSMP user's guide explains how these parts of a region are defined and how Region objects work in general. The perimeter elements of regions are only those which have at least one of their faces on the region boundary.

Attention
Since perimeter nodes are shared between adjacent regions the last value assignment instruction will determine the values that the target variables at these boundary nodes will have after initialisation is complete. This is not the case for other property placements.

Block 4 - (box-shaped models only): assigns boundary conditions using the boundary identifiers defined by the enumeration BOX_BOUNDARY in 'Box.h'. Box-shaped models offer a few extra configuration possibilities. For instance, linear boundary property variations can be assigned, which is not possible for free-form models for which only uniform boundary values can be assigned. For the latter, computations performed on the boundaries can achieve this goal.

Block 5 - Essential conditions that are assigned by setting property condition flags for specifc regions. Again the discriminators 'complete, interior, perimeter' can be used. To assign boundary condition values to irregular models, one first sets the desired property value in the target region and then assigns the intended condition flag to it, i.e. DIRICH or NEUMANN etc. in Block 5.

Any of the data blocks are started and terminated by an empty line.

Apart from the block-structured approach to the configuration file the InputDataManager provides several methods to initialize models created with specific meshing tools, such as Shewchuk's triangle mesher and ICEM's suite of meshing tools.

Computational Settings - is an additional block that can be appended, allowing the user to define the time stepping strategy, duration and times when simulation results shall be output to file.

Again, a blank line indicates the end of this block and users can write any comments, references, and observations made on models as kind of a documentation, following the configuration.

Applicability

The InputDataManager can be used to configure any CSMP model, but its functionality is restricted to that of public interfaces of the Model.

Participants

The data input manager requires a Model to act on- and interacts with the ComputationalSettings object that is used to store runtime information.

Consequences

The decision that CSMP variable names may contain white space forced us to restrict the use of token (string item) separators to the tab keys. Thus every item in any configuration line must be separated by a tab key and any other white space must be avoided (also at the end of lines). Comments can be inserted anywhere into configuration files. To write a comment, start the line with a # sign.

The data input manager allows the user to configure CSMP models without the need for compilation of a program.

configures box-shaped ANSYS models output using ANSYS' csmp input interface

The method is similar to ConfigureFromFile(), version 1, but should be applied only to box-shaped models which already contain the target regions.

These are the characteristics of models generated through the ANSYS_Interface object.

Reading is restricted to blocks 2 to 4.

Input Arguments

The method takes a reference to the model which shall be initialized with the input data and the name of the file from which the data shall be read. The file name has to be specified without extension. The model will automatically append '-configuration.txt' to it.

Returns
The data will be assigned to the input Model object.

Implementation

Boundary conditions can only be assigned to scalar and vector variables, see the documentation of ReadPropertyValue() to learn how CSMP variable values are specified in the input.

Attention
The internal settings that determine which input file blocks are read are as follows:
bool region_specifications ( false ); // regionname from parameter range
bool default_property_values ( true ); // default property values
bool region_property_values ( true ); // regional property values
bool box_boundary_conditions ( true ); // boundary conditions for box-shaped model
bool region_property_conditions ( true ); // essential conditions for regions
bool boundary_conditions ( false ); // boundary conditions for arbitrary-shaped model
bool well_settings ( false ); // well names, locations, rates, ratios
bool computational_settings ( false ); // computational settings

Application Examples

Use this method to configure models for which the meshes were created with the ANSYS suite of simulation tools.

Messages

The reading process is verbose. The method keeps the user informed about the progress and assigned property values are echoed to screen.

FRED was a FRACMAN consortium of Golder Associates, this interface is used in the Fracman GUI.

The agreed file structure for FRED-based CSMP models combines the assigment of material properties with that of boundary conditions and computational settings such as the run duration, time-stepping strategy, and output times.

Input Arguments

The method takes a reference to the model that will be configured and the name of the input file to which the extension '-FRED-input.txt' will be appended.

Returns
The method returns node point locations which represent the intersection of lines representing wells with fracture surfaces. The last method argument is the object into which the computational settings will be stored.

reads data for blocks 1-5, assigning them to box-shaped models

Reads the input data blocks 1-5 (see class documentation) from the user specified '*-configuaration.txt' input file. The method gives the user the possibility to generate regions of elements with certain variable data range and to assign values and essential conditions to them.

Input Arguments

The method takes a reference to the model which shall be initialized with the input data and the name of the file from which the data shall be read. The file name has to be specified without extension. The model will automatically append '-configuration.txt' to it.

Returns
The data will be assigned to the input Model object.

Implementation

Boundary conditions can only be assigned to scalar and vector variables, see the documentation of ReadPropertyValue() to learn how CSP variable values are specified in the input.

Application Examples

Because the method attempts to assign essential conditions to model boundaries identified by the enumeration BOX_BOUNDARY, it should only be for rectangular or box-shaped models which may however contain boundaries that are flagged as IRREGULAR as well. This is the case for box-shaped models with a top surface that represents a topography.

Messages

The reading process is verbose. The title of the input file and potential parsing errors are reported.

key generic configuration method for time-dependent models that can contain Boundary objects

Allows for the costumized configuration of CSMP models including csmp::Boundary

Input Arguments

The method takes a reference to model which shall be initialized with the property values from the input file and the name of the file without the extension '-configuration.txt' which will be appended to the file name automatically.

The boolean variables block1 to block5 enable the user to costumize the reading process. Thus, the desired data blocks can be switched on with their boolean variable values set to true. The role of the different input blocks is to read and create:

block1 - regionname from parameter range.
block2 - assign default property values.
block3 - assign regional property values (i.e. values to existing regions),
block4 - assign standard boundary conditions to box-shaped model.
block5 - assign essential conditions via VARIABLE_FLAG flags to regions.
block6 - assign properties incl flag to csmp::Boundary objects
