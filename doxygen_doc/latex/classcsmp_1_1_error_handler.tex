\doxysubsection{Detailed Description}
The singleton \doxylink{classcsmp_1_1_error_handler}{Error\+Handler} implements an issue reporting scheme to support platform-\/specific message capabilities like error windows or specific options that can be specified for core-\/dumps etc. The error handler further documents the progression of issues that occur during a run so that warnings etc. leading up to an error can be examined in the runtime.\+log file. Thus, the aim is to provide diagnostics of when and under what conditions an error arose.

The \doxylink{classcsmp_1_1_error_handler}{Error\+Handler} classifies (by enumeration), the different messages that are sent to it as INFOs, WARNINGs, ERRORs, and FATAL\+\_\+\+ERRORs\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{\textcolor{keyword}{enum}\ csmp\_error\{\ INFO,\ EXCEPTION,\ WARNING,\ ERROR,\ FATAL\_ERROR\ \};}

\end{DoxyCode}


If a FATAL\+\_\+\+ERROR is reported, the \doxylink{classcsmp_1_1_error_handler}{Error\+Handler} will terminate the run. This role is given to the error handler with its future role as exception handler in mind. Present FATAL\+\_\+\+ERRORs will become recoverable once exception handling is consistently implemented throughout CSMP.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}{}\doxysubsection{\texorpdfstring{Design Intent}{Design Intent}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}
The \doxylink{classcsmp_1_1_error_handler}{Error\+Handler} logs information strings to \textquotesingle{}cout\textquotesingle{} / \textquotesingle{}cerr\textquotesingle{} and to the log file \textquotesingle{}Error\+Handler.\+log\textquotesingle{}. To be able to trace a message to its source, a string that consists of the class and method name from which the message originated must be supplied as first message argument. In case of an overloaded method additional information is included in braces which identifies the called method uniquely, for example\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{ErrorHandler::Notice(\textcolor{keywordtype}{char}*,\ \textcolor{keywordtype}{char}*):}

\end{DoxyCode}


Messages which are written to file, are automatically preceded by a time string which tells the user when the message originated. Since messages may also contain numerical data in the description of the error message the \doxylink{classcsmp_1_1_error_handler}{Error\+Handler} interface is overloaded to accept std\+::string arguments (std\+::string has overloaded operators that allow the method writer to convert numbers to strings). The functionality of the \doxylink{classcsmp_1_1_error_handler}{Error\+Handler} is planned to be extended to handle top level (C++) exceptions. For this purpose the standard exception base classes exception, logic\+\_\+error, and runtime\+\_\+error will be subclassed for CSMP-\/specific error types.

A goal of the exception handling is to store the transient state of a run before it gets aborted such that it can be carried on from this state at a later time, when the error condition has been properly diagnosed.\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
The \doxylink{classcsmp_1_1_error_handler}{Error\+Handler} is used inside high-\/level CSMP objects like the \doxylink{classcsmp_1_1_model}{Model} etc.. Only those which carry enough information so that it makes sense to collect user-\/readable diagnostics from a CSMP run are logged. Atomic generic classes report errors directly to the \textquotesingle{}cerr\textquotesingle{} stream.\hypertarget{classcsmp_1_1_v_data_structure}{}\doxysubsection{\texorpdfstring{Structure}{Structure}}\label{classcsmp_1_1_v_data_structure}
\doxylink{classcsmp_1_1_error_handler}{Error\+Handler} is a base-\/level class using STL maps to store the different types of error messages.\hypertarget{classcsmp_1_1_solver_participants}{}\doxysubsection{\texorpdfstring{Participants}{Participants}}\label{classcsmp_1_1_solver_participants}
A singleton instance(static) is created upon loading the csmp core library.\hypertarget{classcsmp_1_1_time_step_evaluator_collaborations}{}\doxysubsection{\texorpdfstring{Collaborations}{Collaborations}}\label{classcsmp_1_1_time_step_evaluator_collaborations}
\doxylink{classcsmp_1_1_error_handler}{Error\+Handler} uses the functionality of STL maps and the std\+::string class. The \doxylink{classcsmp_1_1_standard___i_o___handler}{Standard\+\_\+\+IO\+\_\+\+Handler} is used in dialogs with a console user. The object \doxylink{class_b_e___time}{BE\+\_\+\+Time} is contained to log the time at which errors occur.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}{}\doxysubsection{\texorpdfstring{Consequences}{Consequences}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}
The consequent usage of the \doxylink{classcsmp_1_1_error_handler}{Error\+Handler} turns it into an \textquotesingle{}Observer\textquotesingle{} object the functionality of which may be widely extended in future implementations. For the time being, the user can use the \textquotesingle{}\texorpdfstring{$\ast$}{*}.log\textquotesingle{} file and the screen output to obtain a detailed progress report for his/her CSMP run. Interaction with the run, however, is still very limited.\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
The \doxylink{classcsmp_1_1_error_handler}{Error\+Handler} stores the message strings in 3 maps corresponding to the message types\+: INFO, WARNING, ERROR. Since only a single FATAL\+\_\+\+ERROR can occur before the run is terminated, it is lumped into the ERROR map. In the log file, all messages are logged sequentially.

The error log file is written by the destructor of the error handler. Because the destructor of a global object is called last, this assures that all messages that arise in the destruction process are logged as well.\hypertarget{group___c_s_m_pglobal_enums_application}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{group___c_s_m_pglobal_enums_application}
