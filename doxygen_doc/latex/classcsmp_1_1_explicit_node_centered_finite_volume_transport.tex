\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
The \doxylink{classcsmp_1_1_explicit_node_centered_finite_volume_transport}{Explicit\+Node\+Centered\+Finite\+Volume\+Transport} module is provided to allow users to perform passive advection and advection of a single non-\/wetting phase in two-\/phase flow simulations. It represents the fastest but CFL dependent transport scheme for arbitrary FE meshes including different FE types and mixes of volume and surface elements. ~\newline


The scheme is also very tolerant in that no specific boundary conditions need to be applied. The value of the advected variable at inflow boundaries is not modified and governs what gets transported into the model domain. ~\newline
\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}{}\doxysubsection{\texorpdfstring{Design Intent}{Design Intent}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}
The scheme has been designed to capitalize on the new generic polytype CVFE technology that is part of CSMP. ~\newline
\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
Use the scheme if the transport velocity field is rapidly changing or invalidated by the transport itself. In this case the scheme is faster that the implicit scheme embodied in the Finite\+Volume\+Transport module which starts to pay off at about CFL=20 or greater. ~\newline


Do not use this scheme when the CFL condition based transport increment leads global advection steps that are smaller than about 1/1,000 of the model length in the direction of the flow. In this case the computations would be prohibitively slow.\hypertarget{classcsmp_1_1_v_data_structure}{}\doxysubsection{\texorpdfstring{Structure}{Structure}}\label{classcsmp_1_1_v_data_structure}
The explicit advection scheme consists out of the three modules\+: ~\newline


\doxylink{classcsmp_1_1_explicit_node_centered_finite_volume_transport}{Explicit\+Node\+Centered\+Finite\+Volume\+Transport} Explicit\+Finite\+Volume\+Algorithm Explicit\+Finite\+Volume\+Processor

The user will only interact with the \doxylink{classcsmp_1_1_explicit_node_centered_finite_volume_transport}{Explicit\+Node\+Centered\+Finite\+Volume\+Transport} module, but the Explicit\+Finite\+Volume\+Algorithm is used to manage the accumulation and output of the solution in each transport step, and the Explicit\+Finite\+Volume\+Processor class facilitates the generation of the finite-\/volume stencils from each finite element, so that the accumulation can proceed on an element by element basis and no FV mesh needs to be stored.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_collaboration}{}\doxysubsection{\texorpdfstring{Collaboration}{Collaboration}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_collaboration}
The scheme collaborates with the finite elements of the current model.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}{}\doxysubsection{\texorpdfstring{Consequences}{Consequences}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}
This implementation of the scheme cannot be restricted to Regions, but always needs to be applied to the entire model, i.\+e. \doxylink{classcsmp_1_1_model}{Model}. ~\newline


Currently it also only works for 3D models. Surface computations can still be done if the mesh consists entirely of surface elements in 3D space.\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
The flux-\/balances are computed for all finite volumes including those which are located on the boundaries of the \doxylink{classcsmp_1_1_region}{Region} or \doxylink{classcsmp_1_1_model}{Model} to which the transport scheme is applied. They are compensated for also on all domain boundaries. ~\newline

It will advect using that time interval, assuming the user has externally determined that this is the correct time interval length. In contrast with Advect\+Variable(, this method does not break the time interval into sub-\/parts and guarantee stability. This also means that the courant increment is not checked for in this method (and should be, externally, of course).
