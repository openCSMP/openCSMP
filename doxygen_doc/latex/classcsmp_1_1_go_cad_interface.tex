Given a three-\/dimensional CSMP model, \doxylink{classcsmp_1_1_go_cad_interface_aa2fce00574c73522de5050bad574c87a}{Output\+Variable\+To\+TSolid()} creates a Go\+Cad TSolid dataset for the indicated variable in a subregion of the model which was previously identified as a \doxylink{classcsmp_1_1_region}{Region} object. The variable is to a textfile with the Go\+Cad specific extension \textquotesingle{}.so\textquotesingle{}. The TSolid format is described in the Go\+Cad manual, Appendix B (p. B-\/14) and consists of\+:

Go\+Cad header, PVTRX list\+: node coordinate and property data listed by node number, TETRA list\+: nodes per tetrahedral finite element, END end of file specifier

Importantly, a TSolid file written by Go\+Cad will contain constraint point lists preceding each TETRA block. In constrast to CSMP jargon, a constraint point in Go\+Cad is a node point which lies on an object boundary. In this fashion, the model volume is described object by object. ~\newline
\hypertarget{group___c_s_m_pglobal_functions_arguments}{}\doxysubsection{\texorpdfstring{Input Arguments}{Input Arguments}}\label{group___c_s_m_pglobal_functions_arguments}

This argument is optional. The first argument is the name of the file to which the TSolid dataset is written to and to whose name the timestep is appended. If the timestep is not specified, a zero will be appended to the filename before the extension \textquotesingle{}.so\textquotesingle{}. The second argument is the name of the group object defining the model subregion over which the variable (third argument) shall be output. ~\newline
\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
The method uses a \doxylink{classcsmp_1_1_gocad_header}{Gocad\+Header} class object to write the file and the property class header in the TSolid file.

If the method is used to output element properties, these will be mapped onto the nodes, since Go\+Cad only permits nodal variables. To achieve the mapping, intermediate variable vectors are created and all nodes of each element are assigned the corresponding element property value. This strategy has the disadvantage that nodes with a higher ID number will overwrite the property values on nodes with lower numbers. The effect may be a rugged appearance of element property boundaries. User suggestions are welcome to overcome this deficiency.\hypertarget{group___c_s_m_pglobal_enums_application}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{group___c_s_m_pglobal_enums_application}

The Go\+Cad TSurf format is defined in Appendix B of the Go\+Cad manual (p. B-\/10). In brief, it is a list of the following items\+:

Outputs a physical variable from the \doxylink{classcsmp_1_1_model}{Model} to a Go\+Cad TSurf object which is stored into a textfile with the recommended extension \textquotesingle{}.ts\textquotesingle{} for direct import into Go\+Cad as Go\+Cad object.

The Go\+Cad TSurf format is defined in Appendix B of the Go\+Cad manual (p. B-\/10). In brief, it is a list of the following items\+:

a Go\+Cad header, PVTRX information\+: vertex coordinates and associated property values, TRGL triangle connectivity information\+: the numbers of nodes in each triangle, END the end of file marker.\hypertarget{group___c_s_m_pglobal_functions_arguments}{}\doxysubsection{\texorpdfstring{Input Arguments}{Input Arguments}}\label{group___c_s_m_pglobal_functions_arguments}
\doxylink{classcsmp_1_1_go_cad_interface_ad53bbd900d0f59ef4cf9224d05f8d4c4}{Output\+Variable\+To\+TSurface()} takes three arguments, the name of the output file to which the third argument which is the timestep and the extension \textquotesingle{}.ts\textquotesingle{} are appended. The second argument specifies the variable which is output to file. Thus far, if variables ~\newline
 are element variables they will still be stored on the nodes in the output file. This may cause boundary nodes of regions appear oddly valued, since the element node values will overlap with eachother depending on the node numbering in the model.\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
\doxylink{classcsmp_1_1_go_cad_interface_ad53bbd900d0f59ef4cf9224d05f8d4c4}{Output\+Variable\+To\+TSurface()} uses several atomistic class objects to represent gocad formats, these are the \doxylink{classcsmp_1_1_gocad_header}{Gocad\+Header} and the \doxylink{classcsmp_1_1_gocad_property_class_header}{Gocad\+Property\+Class\+Header} objects.

The method only works for two-\/dimensional models. 3D models must be output as Go\+Cad TSolid objects (see corresponding documentation).

Integration\+Point variables cannot be output to TSurf files.\hypertarget{group___c_s_m_pglobal_enums_application}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{group___c_s_m_pglobal_enums_application}

Top level method to read ASCII text files from the geometric modeling program Go\+Cad which were output in the TSolid format. The method just reads the header of the Go\+Cad file diagnosing its format and interpreting which datasets are contained. If the file header can be interpreted correctly, control is transferred to Read\+TSolid() which will read the data from the TSolid file.

Read\+Gocad\+Text() expects either no variable or the variable \textquotesingle{}permeability\textquotesingle{} to be specified in the Go\+Cad output file. At the moment, the method only supports the reading of a single property.
