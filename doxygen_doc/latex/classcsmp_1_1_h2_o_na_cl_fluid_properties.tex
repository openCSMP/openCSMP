\doxylink{classcsmp_1_1_h2_o_na_cl_fluid_properties}{H2\+ONa\+Cl\+Fluid\+Properties} is an single interface to H2O single-\/, two-\/, and three-\/phase properties in a porous medium via an equation of state. This information might also be obtained from the individual Lookup\+Tables for the H2\+O\+\_\+na\+Cl system but would require a detailed knowledge of the phase relations and thermodynamics involved and would be incomplete because some properties vary with the exact properties of the rock matrix (e.\+g., the compressibility of a twophase liquid+vapor mixture is a function of the rock\textquotesingle{}s heat capacity and porosity, see Grant\&Sorey (1979), The Compressibility and Hydraulic Diffusivity of a Water-\/\+Steam Flow, \doxylink{classcsmp_1_1_water}{Water} Resources Research, 15, 3, 684-\/686).

\doxylink{classcsmp_1_1_h2_o_na_cl_fluid_properties}{H2\+ONa\+Cl\+Fluid\+Properties} eliminates the need of such a detailed implementation in terms of the interface of the various H2\+O-\/\+Na\+Cl lookup tables (the list of which is apparent from the \#include statements in this file) by the user.\hypertarget{classcsmp_1_1_upwind_control_visitor_usage}{}\doxysubsection{\texorpdfstring{Usage}{Usage}}\label{classcsmp_1_1_upwind_control_visitor_usage}
A \doxylink{classcsmp_1_1_h2_o_na_cl_fluid_properties}{H2\+ONa\+Cl\+Fluid\+Properties} is instantiated with seven constrcutor arguments. These are temperature in Celsius, pressure in bar, Na\+Cl content in mole fraction, specific fluid enthalpy (in J/kg), the rock\textquotesingle{}s heat capacity in J/kg/K, the rock\textquotesingle{}s density in kg/m3, and the porosity (dimensionless). These are passed as const references to the respective existing objects in the user\textquotesingle{}s code. \doxylink{classcsmp_1_1_h2_o_na_cl_fluid_properties}{H2\+ONa\+Cl\+Fluid\+Properties} has an internal mechanism that makes sure that whenever it is queried (except for the Report... functions, see below) it checks and updates its internal placeholders to the current values of these variables, i.\+e., the user does NOT have to trigger an update. Although \doxylink{classcsmp_1_1_h2_o_na_cl_fluid_properties}{H2\+ONa\+Cl\+Fluid\+Properties} can be used standalone, it is most often applied as a member of Na\+Cl\+H2\+OProperties\+Visitor.

For accurate computation in the pure H2O limit, \doxylink{classcsmp_1_1_h2_o_na_cl_fluid_properties}{H2\+ONa\+Cl\+Fluid\+Properties} has an instance of \doxylink{classcsmp_1_1_h2_o_fluid_properties}{H2\+OFluid\+Properties} as a member.

The most important interfaces return objects of type \doxylink{structcsmp_1_1_fluidproperties}{Fluidproperties}. These are\+:

(1) Liquid\+Properties(), Vapor\+Properties(), Salt\+Properties(), and Bulk\+Properties(). These determine the fluid state and properties primarily at the given temperature, pressure, and composition. Specific fluid enthalpy comes into play if the three-\/phase (vapor-\/liquid-\/halite) case or the pure H2O two-\/phase (vapor-\/liquid) or pure Na\+Cl twophase (Halite+melt) case is encountered. Very low pressure cases along the respective sublimation curves are outside the range of validity as is the low-\/temperature cases involving ice or hydrohalite. Those conditions where enthalpy is required become active when temperature is identical to the temperature at the phase boundary within 5 x the available numerical precision of double on the given platform.

If one of these member functions is invoked, all properties are computed. To avoid re-\/computation(\texorpdfstring{$\ast$}{*}), properties of the other two may the also be extracted via the respective Report... functions described below. This has changed from previous versions\+: the functions used to have an internal check that avoided re-\/computation in case that t,p,h,x,cp\+\_\+rock,rho\+\_\+rock and phi didn\textquotesingle{}t change. This has currently been disabled and may be re-\/activated after intense testing of this new version has been done.

(2) Report\+Liquid\+Properties(), Report\+Vapor\+Properties(), Report\+Salt\+Properties(), Report\+Bulk\+Properties(). These should be used with care. These functions bypass the internal automatic update of temperature etc. and will hence return the fluid properties as they were computed after the last internal update. This is likely to disagree with the current values of temperature, pressure etc. in the user\textquotesingle{}s code. However, if one of the above Liquid\+Properties(), Vapor\+Properties(), Salt\+Properties(), or Bulk\+Properties() functions has been called, properties for the other two calls have already been computed and might equally well be extracted via the respective Report... functions (e.\+g.\+: if you called Bulk\+Properties(), you can safely extract vapor, liquid, and salt properties by immediately afterwards calling Report\+Vapor\+Properties(), Report\+Liquid\+Properties(), and Report\+Salt\+Properties().\hypertarget{classcsmp_1_1_upwind_control_visitor_dependencies}{}\doxysubsection{\texorpdfstring{Dependencies}{Dependencies}}\label{classcsmp_1_1_upwind_control_visitor_dependencies}
