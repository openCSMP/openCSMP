\href{mailto:thomas.driesner@erdw.ethz.ch}{\texttt{thomas.\+driesner@erdw.\+ethz.\+ch}}\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
\doxylink{classcsmp_1_1_h2_o_thermal_equilibrator}{H2\+OThermal\+Equilibrator} finds the temperature at which rock and a pure H2O fluid are in thermal equilibrium at a given pressure. This is done by an isobaric bisection iteration through the water phase diagram, which compares the total enthalpy at a test temperature t\+\_\+eq (H\+\_\+test = mass\+\_\+rock\texorpdfstring{$\ast$}{*}enthalpy\+\_\+rock(t\+\_\+eq) + mass\+\_\+fluid\texorpdfstring{$\ast$}{*}enthalpy\+\_\+fluid(t\+\_\+eq) ) with the enthalpy value H\+\_\+current\+\_\+eq that was provided by the transport code (specifically\+: H2\+OProperties\+Visitor).

Currently (as of January 28, 2011) iteration starts from an upper temperature limt tmax at 1000C and a lower one at 5C and follows true bisection. The actual computation of fluid properties as well as determination of fluid phase state is done by an \doxylink{classcsmp_1_1_h2_o_fluid_properties}{H2\+OFluid\+Properties} object.\hypertarget{classcsmp_1_1_upwind_control_visitor_usage}{}\doxysubsection{\texorpdfstring{Usage}{Usage}}\label{classcsmp_1_1_upwind_control_visitor_usage}
Instantiate \doxylink{classcsmp_1_1_h2_o_thermal_equilibrator}{H2\+OThermal\+Equilibrator} with references to various properties seen as constructor arguments. It is YOUR responsibility to make sure they are properly up to date when \doxylink{classcsmp_1_1_h2_o_thermal_equilibrator}{H2\+OThermal\+Equilibrator} ist called.

The main calls are Liquid(), Vapor(), and Bulk(). Calling one of them triggers a full equilibration (except if the values of those properties referenced in the constructor havn\textquotesingle{}t changed, then the last equilibration results are assumed to be correct). It returns fluid property values as \doxylink{structcsmp_1_1_fluidproperties}{Fluidproperties} objects (see documentation there for full property set). These fluidproperties refer to the phase indicate by the name of the function call.

Another set of calls -\/ Report\+Liquid\+Properties(const double\& t, const double\& p, const double\& h), Report\+Vapor\+Properties(const double\& t, const double\& p, const double\& h), Report\+Bulk\+Properties(const double\& t, const double\& p, const double\& h) -\/ lets you query the properties for a desired combination of temperature, pressure and specific fluid enthalpy. Use with care because getting the logic for this right in a simulation context is non-\/trivial. ~\newline

\begin{DoxyItemize}
\item Convergence is assumed once the difference (H\+\_\+test-\/\+H\+\_\+current\+\_\+eq) divided by the fluid mass is less than 10\texorpdfstring{$^\wedge$}{\string^}-\/4 of the fluid\textquotesingle{}s specific enthalpy. Wether a tighter criterion is necessary (and can successfully be fulfilled by this method) remains subject to further testing.
\item Care has been taken that the \doxylink{classcsmp_1_1_h2_o_fluid_properties}{H2\+OFluid\+Properties} object catches problems arising from numerical precision when being close to phase boundaries (e.\+g. when t\+\_\+eq is within numerical precision identical to the boiling temperature and a vapor state is determined although the actual state is liquid). However, this has not been tested in great detail. Further details will be added to this section with time.
\item The current bisection scheme is likely to be small. If a Newton-\/like component is added, the treatment of rock heat capacity / enthalpy and the prediction of tmin / tmax from t\+\_\+eq may become non-\/trivial
