class csmp\+::\+Input\+Data\+Manager$<$ dim $>$}
input of parameter values from block-\/structured text file. 

\begin{DoxyAuthor}{Author}

S. Geiger 

S.\+G. Roberts 
\end{DoxyAuthor}

\end{DoxyDate}
\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
To have an ASCII-\/file based interface to CSMP which allows to assign material properties and initial conditions to models and their subregions as identified by unique names (of groups). ~\newline


\doxylink{classcsmp_1_1_boundary}{Boundary} and essential conditions should also be assignable via condition flags and this approach needs to work in 1-\/3D and both for box-\/ and for freeform models. ~\newline


Since many meshing tools do not allow to assign names to subregions of models / meshes, but subregions and model internal and external boundaries are identified by integer or floating point (material property) values, this interface should also provide the possibility to create named model subregions from property values and ranges. The only possible properties for this purpose inside of CSMP are element properties. This is because each subregion must at least consist of one finite element.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}{}\doxysubsection{\texorpdfstring{Design Intent}{Design Intent}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}
A simple design is achieved by dividing the input data into five different data blocks. The user decides which blocks to read, by setting boolean flag arguments to \doxylink{classcsmp_1_1_input_data_manager_aad889f893c47a359162fb89cedfba606}{Configure\+From\+File()}\+:

Block 1 -\/ to define named regions of elements with characteristic values of element properties. ~\newline


Block 2 -\/ to set default property values for the entire model. These can get overwritten in individual subregions by the values and flags supplied in the data blocks 3-\/5.

Block 3 -\/ property values for model subregions. The user can determine whether these values are applied to the entire subregion (option=COMPLETE), its boundary (option=PERIMETER), or only the interior of the region (option=INTERIOR). The CSMP user\textquotesingle{}s guide explains how these parts of a region are defined and how \doxylink{classcsmp_1_1_region}{Region} objects work in general. The perimeter elements of regions are only those which have at least one of their faces on the region boundary.

\begin{DoxyAttention}{Attention}
Since perimeter nodes are shared between adjacent regions the last value assignment instruction will determine the values that the target variables at these boundary nodes will have after initialisation is complete. This is not the case for other property placements.
\end{DoxyAttention}
Block 4 -\/ (box-\/shaped models only)\+: assigns boundary conditions using the boundary identifiers defined by the enumeration \doxylink{group___c_s_m_pglobal_enums_ga8e4421c3cd02f67e535bceb2dc74bfb6}{BOX\+\_\+\+BOUNDARY} in \textquotesingle{}\doxylink{_box_8h}{Box.\+h}\textquotesingle{}. Box-\/shaped models offer a few extra configuration possibilities. For instance, linear boundary property variations can be assigned, which is not possible for free-\/form models for which only uniform boundary values can be assigned. For the latter, computations performed on the boundaries can achieve this goal.

Block 5 -\/ Essential conditions that are assigned by setting property condition flags for specifc regions. Again the discriminators \textquotesingle{}complete, interior, perimeter\textquotesingle{} can be used. To assign boundary condition values to irregular models, one first sets the desired property value in the target region and then assigns the intended condition flag to it, i.\+e. DIRICH or NEUMANN etc. in Block 5.

Any of the data blocks are started and terminated by an empty line. ~\newline


Apart from the block-\/structured approach to the configuration file the \doxylink{classcsmp_1_1_input_data_manager}{Input\+Data\+Manager} provides several methods to initialize models created with specific meshing tools, such as Shewchuk\textquotesingle{}s triangle mesher and ICEM\textquotesingle{}s suite of meshing tools.

Computational Settings -\/ is an additional block that can be appended, allowing the user to define the time stepping strategy, duration and times when simulation results shall be output to file.

Again, a blank line indicates the end of this block and users can write any comments, references, and observations made on models as kind of a documentation, following the configuration.\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
The \doxylink{classcsmp_1_1_input_data_manager}{Input\+Data\+Manager} can be used to configure any CSMP model, but its functionality is restricted to that of public interfaces of the \doxylink{classcsmp_1_1_model}{Model}.\hypertarget{classcsmp_1_1_solver_participants}{}\doxysubsection{\texorpdfstring{Participants}{Participants}}\label{classcsmp_1_1_solver_participants}
The data input manager requires a \doxylink{classcsmp_1_1_model}{Model} to act on-\/ and interacts with the \doxylink{classcsmp_1_1_computational_settings}{Computational\+Settings} object that is used to store runtime information.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}{}\doxysubsection{\texorpdfstring{Consequences}{Consequences}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}
The decision that CSMP variable names may contain white space forced us to restrict the use of token (string item) separators to the tab keys. Thus every item in any configuration line must be separated by a tab key and any other white space must be avoided (also at the end of lines). Comments can be inserted anywhere into configuration files. To write a comment, start the line with a \# sign.

The data input manager allows the user to configure CSMP models without the need for compilation of a program.\hypertarget{classcsmp_1_1_visitor_examples}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{classcsmp_1_1_visitor_examples}

FRED was a FRACMAN consortium of Golder Associates, this interface is used in the Fracman GUI. 

The agreed file structure for FRED-\/based CSMP models combines the assigment of material properties with that of boundary conditions and computational settings such as the run duration, time-\/stepping strategy, and output times.\hypertarget{group___c_s_m_pglobal_functions_arguments}{}\doxysubsection{\texorpdfstring{Input Arguments}{Input Arguments}}\label{group___c_s_m_pglobal_functions_arguments}

\begin{DoxyReturn}{Returns}
The method returns node point locations which represent the intersection of lines representing wells with fracture surfaces. The last method argument is the object into which the computational settings will be stored.
\end{DoxyReturn}
