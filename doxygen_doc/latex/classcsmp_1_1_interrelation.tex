\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
Traditionally, locally resolvable interdependencies of dependent model variables are computed in so-\/called \textquotesingle{}post-\/processing\textquotesingle{} operations which involve looping through arrays of nodes and elements, applying mathematical relationships to compute the \doxylink{structvariable}{variable(s)} of interest. This procedure is error prone, firstly, because of the danger of writing beyond array bounds which the top level user is not necessarily familiar with; secondly, the results of such calculations are not tested before they are written into the global arrays; and, thirdly, if one has many of such calculation procedures inside of a time-\/stepping loop, it becomes hard to track which post-\/processing procedure depends on a previous one, to determine an execution order which must be adhered to.

The \doxylink{classcsmp_1_1_interrelation}{Interrelation} class represents an attempt to overcome these dangers by encapsulating post-\/processing operations into modules. This design achieves the following objectives\+:

Firstly, the loop operations and variable access is embedded into the \doxylink{classcsmp_1_1_interrelation}{Interrelation} class. The user must only associate an \doxylink{classcsmp_1_1_operand}{Operand} object with the variable which he can subsequently use in the mathematical expressions.

Secondly, The result of such a calculation is tested before it is stored back into the Memory\+Manager. This test determines whether the result lies in a physically meaningful range for which other Interrelations that use the variable as an input, have been tested (This is essential to ascertain the correctness of a complex simulation). ~\newline


Thirdly, Interrelations always modify only a single variable. This restriction allows them to be managed by an Interrelation\+Manager which automatically determines an \doxylink{classcsmp_1_1_interrelation}{Interrelation} computation sequence in time-\/stepping loops.

There is also a need to used node variables in the computation of element properties and so forth. For these type of calculations, the \doxylink{classcsmp_1_1_interrelation}{Interrelation} class has the capability of taking property averages or apply other useful strategies through the use of \doxylink{classcsmp_1_1_operand}{Operand} objects.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}{}\doxysubsection{\texorpdfstring{Design Intent}{Design Intent}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}
In the CSMP modeling code, all calculations that do not involve the inversion of a global solution matrix are done by passing \doxylink{classcsmp_1_1_interrelation}{Interrelation} subclass instances to \doxylink{classcsmp_1_1_model}{Model} objects. An example of an \doxylink{classcsmp_1_1_interrelation}{Interrelation} would be the calculation of the hydraulic conductivity from the permeability by dividing permeability by viscosity and assigning the result to the variable conductivity. The code that does this is provided as the class \textquotesingle{}Conductivity\+From\+Perm\textquotesingle{} as defined in a header file with the same name. ~\newline
\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
All calculations in a CSP model which can be done in an element by element fashion or just by looking at node or constraint point variables only, should be encapsulated into Interrelations. Exceptions from this rule are global expressions which one may want to write using \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} objects. Also, for the special case where a well-\/understood process modifies several variables simultaneously, which would require multiple interrelations, a visitor object may be better suited to achieve the computation goal. ~\newline


Importantly, Interrelations can be restricted such that they apply only to subregions of a model identified as \doxylink{classcsmp_1_1_region}{Region} objects. This capability allows, for instance, to compute a magmatic fluid source within a cooling granite without the overhead of traversing the entire mesh.\hypertarget{classcsmp_1_1_v_data_structure}{}\doxysubsection{\texorpdfstring{Structure}{Structure}}\label{classcsmp_1_1_v_data_structure}
The \doxylink{classcsmp_1_1_interrelation}{Interrelation} class is a base class from which the user inherits a subclass object for instance \textquotesingle{}Conductivity\+From\+Perm\textquotesingle{} which contains the mathematical expression which the user wants to apply. Inheriting such a subclass involves the following steps\+:

Firstly, the user must define a notation for his mathematical expression by associating a \doxylink{classcsmp_1_1_operand}{Operand} objects with the global physical variables of interest (for the above example)\+:

An \doxylink{classcsmp_1_1_interrelation}{Interrelation} object always contains Operands and a reference to the \doxylink{classcsmp_1_1_property_database}{Property\+Database} in order to register and manage the physical variables.\hypertarget{classcsmp_1_1_time_step_evaluator_collaborations}{}\doxysubsection{\texorpdfstring{Collaborations}{Collaborations}}\label{classcsmp_1_1_time_step_evaluator_collaborations}
The \doxylink{classcsmp_1_1_interrelation}{Interrelation} collaborates with \doxylink{classcsmp_1_1_model}{Model} and \doxylink{classcsmp_1_1_region}{Region} objects in order to compute the desired properties. To apply an \doxylink{classcsmp_1_1_interrelation}{Interrelation} to a model just submitt it to the \doxylink{classcsmp_1_1_model}{Model}\+:

Conductivity\+From\+Perm my\+\_\+interrelation( var\+\_\+database\+\_\+reference ); model.\+Apply( my\+\_\+interrelation );\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}{}\doxysubsection{\texorpdfstring{Consequences}{Consequences}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}
To make use of the \doxylink{classcsmp_1_1_interrelation}{Interrelation} capability of CSP one must define and compile \doxylink{classcsmp_1_1_interrelation}{Interrelation} subclasses. A small library of these is provided but the intend is to build a large moderated internet repository of \doxylink{classcsmp_1_1_interrelation}{Interrelation} objects from which all CSP users can profit and to which they can submit their own \doxylink{classcsmp_1_1_interrelation}{Interrelation} subclasses. ~\newline
\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
The \doxylink{classcsmp_1_1_interrelation}{Interrelation} uses a conditional loop within its \doxylink{classcsmp_1_1_interrelation_a406a9abb7bfe1f137609706b7d284ced}{Apply()} interface to establish the input values for each calculation. It tests the calculation results with \doxylink{classcsmp_1_1_interrelation_a33099fc5e139eae825e6e7af735942e9}{Result\+Within\+Range()}, before these are communicated back to the \doxylink{classcsmp_1_1_model}{Model} object.

If an interrelation subclass involves scalar, vector, and/or tensor variables simultaneously, you can access these variables directly by using the Assign\+To() method of the \doxylink{classcsmp_1_1_operand}{Operand} class. This allows you to make use of the rich interfaces of the Scalar-\/, Vector-\/, and \doxylink{classcsmp_1_1_tensor_variable}{Tensor\+Variable} classes.\hypertarget{classcsmp_1_1_visitor_examples}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{classcsmp_1_1_visitor_examples}
As already discussed above, one must define and compile \doxylink{classcsmp_1_1_interrelation}{Interrelation} subclasses to make use of the \doxylink{classcsmp_1_1_interrelation}{Interrelation} capability of CSP. The steps involved in this process are described in more detail below\+:


\begin{DoxyEnumerate}
\item \doxylink{classcsmp_1_1_test}{Test} the interrelation among variables that you would like to express. This may involve graphing and designing the \doxylink{classcsmp_1_1_interrelation}{Interrelation} in matlab or Mathematica or doing a curve fit through some experimental data within Excel. You will also have to identify the value range for each of the involved variables. Within this value range your mathematical formulation must produce meaningful results. This value range should be at least as wide as the value range that you specified in the variable database text file from which the programm initializes its variable storage. This is extremely important since it is the only way of ascertaining that the CSP code produces correct results once your model becomes complex and contains several interrelations. ~\newline

\item Define your notation and make each symbol a reference to an \doxylink{classcsmp_1_1_operand}{Operand} object. These references should be private data members of your subclass which you define through public derivation from the \doxylink{classcsmp_1_1_interrelation}{Interrelation} class. Importantly, if you don\textquotesingle{}t make Operands references, you will create new variables and your calculation will either not read any of the variable values stored in the \doxylink{classcsmp_1_1_model}{Model} object, or your calculation result will not be transmitted back into the \doxylink{classcsmp_1_1_model}{Model}.
\item Register your variables in the constructor of your derived class. In C++ all references must be initialized in the constructor. First, you construct the base class, then you use the base class method \doxylink{classcsmp_1_1_interrelation_a77c4acf6321b0f95825bb662931bfd93}{Global\+Property()} to register the involved variables and finally you define which of these variables will store the result of your calculation. This is done with the base class method Define\+Result\+Property(). You also have to provide the \doxylink{classcsmp_1_1_interrelation}{Interrelation} with output conditions (use method Output\+Conditions(). ~\newline
 The use of these conditions is to prevent the \doxylink{classcsmp_1_1_interrelation}{Interrelation} from overwriting variable values that you have fixed (e.\+g. DIRICH conditions) or to read variables that have not yet a meaningful value. ~\newline

\item Define your own version of the pure virtual member function \doxylink{classcsmp_1_1_interrelation_a416837f708198b42b157be411d01ec96}{Calculate()} of the \doxylink{classcsmp_1_1_interrelation}{Interrelation} base class. This method will contain your mathematical formulation of the interrelation written using a normal notation involving \texorpdfstring{$\ast$}{*} / + -\/ \texorpdfstring{$<$}{<} \texorpdfstring{$>$}{>} \texorpdfstring{$<$}{<}= \texorpdfstring{$>$}{>}= and other mathematical operations as are defined as overloaded operators of the \doxylink{classcsmp_1_1_operand}{Operand} class. Avoid the construction of too many temporaries within this method. If you need many, make them static such that they do not get destructed when the method goes out of scope. Also, if you write something like\+: \begin{DoxyVerb}K += b + c - d * 24.5;
\end{DoxyVerb}

\end{DoxyEnumerate}

you will automatically create a 4 temporary Operands (why ? -\/ make this a little exercise). ~\newline



\begin{DoxyEnumerate}
\item Decide where to apply your \doxylink{classcsmp_1_1_interrelation}{Interrelation} and pass it to the \doxylink{classcsmp_1_1_model}{Model} which will call the \doxylink{classcsmp_1_1_interrelation}{Interrelation} method \doxylink{classcsmp_1_1_interrelation_a406a9abb7bfe1f137609706b7d284ced}{Apply()}, that performs a range check on the values that your calculation produces. ~\newline

\item You have to define the application domain, if you want to have your interrelation applied only to a group of elements rather than the \doxylink{classcsmp_1_1_model}{Model}. Use the method Restrict\+Application\+To() to achieve this.
\end{DoxyEnumerate}

The calculations that you can perform with \doxylink{classcsmp_1_1_interrelation}{Interrelation} subclasses are limited. You can only calculate result variables that are on the same or a higher level in the \doxylink{classcsmp_1_1_model}{Model} storage hierarchy. For instance you can calculate an element property from node, or constraint point property, but not the other way around. Use a visitor and the Parent references of the \doxylink{classcsmp_1_1_node}{Node} or Integration\+Point classes to do this. Also if you calculate an element property from node property values, the interrelation will use an average over the nodes rather than individual values in the calculation. ~\newline
 If this is too limiting for you than you can overrule the baseclass methods with your own method. Before you do that, however, consider to do your calculation as postprocessng operations of an Algorithm or via a \doxylink{classcsmp_1_1_visitor}{Visitor} object. ~\newline

A few restrictions apply with regard to the placement of the output variable and the placement of the variables which can be employed in an interrelation\+:

If the output variable is a node or constraint point variable, the interrelation must only involve node or constraint point variables, respectively. To explain why, let\textquotesingle{}s assume that one of the input variables was an element variable but the output variable would be a node variable. Since the node simultaneously belongs to several elements whose properties may vary greatly, it is undefined from which element the interrelation should attain the element property input value. For this reason this type of interrelation is not supported.

If the output variable is an element variable but the calculation employs node and/or constraint point variables, \doxylink{classcsmp_1_1_interrelation_a406a9abb7bfe1f137609706b7d284ced}{Apply()} uses the Average() interface of the \doxylink{classcsmp_1_1_element}{Element} to obtain a mean value of the node property. In many cases, this is legitimate but there are cases where this is not so. For instance, if you have a depth-\/dependent nodal property and two adjacent triangular elements that break up a square, one of the elements will have two nodes at the top of the square and the other one has two at the bottom. The computed mean value will be different in these two elements which may be reflected in the result property.

Importantly, interrelations are but one way of computing local interdependencies of physical variables. Please refer to the documentation of the \doxylink{classcsmp_1_1_visitor}{Visitor} base class to see how one can achieve more flexibility. Also, in a CSMP mesh each node or constraint point knows its parent elements which are stored in counterclockwise (righthandrule) fashion in a corresponding vector (see \doxylink{classcsmp_1_1_node}{Node} and Integration\+Point documetation). This knowledge may be employed to compute node properties from element properties.

Finally, since each element knows its neighbors, mesh sweeps may be instrumentalized via visitor objects if so desired.\hypertarget{group___c_s_m_pglobal_enums_application}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{group___c_s_m_pglobal_enums_application}
Is called by the \doxylink{classcsmp_1_1_model}{Model} when the interrelation is passed to it using the \doxylink{classcsmp_1_1_interrelation_a406a9abb7bfe1f137609706b7d284ced}{Apply()} interface.\hypertarget{group___c_s_m_pglobal_functions_messages}{}\doxysubsection{\texorpdfstring{Messages}{Messages}}\label{group___c_s_m_pglobal_functions_messages}
