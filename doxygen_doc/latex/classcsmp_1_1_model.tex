\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
Finite-\/element models typically are characterized by arrays of data that need to be accessed via complex indexing operations and whose interconnectedness is not explicit. Also it is relatively error prone to change the size of these arrays at runtime and to update the connectivity of represented finite elements. Tohe design of the \doxylink{classcsmp_1_1_model}{Model} class was therefore motivated by the need to hide this complexity from the user such that he/she can focus their undivided attention on the geological complexity of the problem at hand.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}{}\doxysubsection{\texorpdfstring{Design Intent}{Design Intent}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}
The design intent was to have an object representation of the mass and space occupancy of a real world system of interest. One should be able to work with and observe this system through the interfaces of the \doxylink{classcsmp_1_1_model}{Model} object.\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
A \doxylink{classcsmp_1_1_model}{Model} representation can be built for any geometrical model which represents a finite-\/element discretization of a real-\/world system. Computations on a \doxylink{classcsmp_1_1_model}{Model} are carried out through its interface \doxylink{classcsmp_1_1_model_a1f470e567edc05fb61d72ba12dbda6b8}{Apply()}. Through this interface you can carry out finite-\/element computations specified by Algorithms or own types derived from the classes Algorithm, and \textquotesingle{}Algorithm\textquotesingle{}. You can also calculate interrelations among variables (including the dependent variables that are computed at each timestep). You do this with your own classes that you derive from the \doxylink{classcsmp_1_1_interrelation}{Interrelation} base class. An example for such an Interrelation-\/derived calculation would be to calculate a permeability that is dependent on fluid pressure. Any derived algorithm or interrelation can also be restricted to Regions of Elements inside the \doxylink{classcsmp_1_1_model}{Model}.\hypertarget{classcsmp_1_1_v_data_structure}{}\doxysubsection{\texorpdfstring{Structure}{Structure}}\label{classcsmp_1_1_v_data_structure}
The \doxylink{classcsmp_1_1_model}{Model} is an agglomerate of objects representing the finite-\/element mesh, implemented as a connectivity scheme and a storage scheme for physical variables that are assigned to nodes, constraint points, or elements themselves. Regions of elements that make up geological entities in the model are referred to as \doxylink{classcsmp_1_1_region}{Region} objects.

The \doxylink{classcsmp_1_1_model}{Model} contains a class hierarchy of \doxylink{classcsmp_1_1_region}{Region}, \doxylink{classcsmp_1_1_element}{Element}, Integration\+Point, and \doxylink{classcsmp_1_1_node}{Node} objects. Their connections reflect the connectivity of the mesh and they are handled internally by the \doxylink{classcsmp_1_1_mesh_manager}{Mesh\+Manager}. The complementary Memory\+Manager object manages the storage for the distributed physical variables of a computation. The \doxylink{classcsmp_1_1_property_database}{Property\+Database} object keeps track of the existing properties, their storage locations and specifications.\hypertarget{classcsmp_1_1_solver_participants}{}\doxysubsection{\texorpdfstring{Participants}{Participants}}\label{classcsmp_1_1_solver_participants}
The \doxylink{classcsmp_1_1_model}{Model} functionality is instrumentalized through instances of \doxylink{classcsmp_1_1_node}{Node}, Integration\+Point, and \doxylink{classcsmp_1_1_element}{Element} classes managed by the \doxylink{classcsmp_1_1_mesh_manager}{Mesh\+Manager}; basic CSMP variables managed by the Memory\+Manager; a \doxylink{classcsmp_1_1_property_database}{Property\+Database}, and a map of Regions.\hypertarget{classcsmp_1_1_time_step_evaluator_collaborations}{}\doxysubsection{\texorpdfstring{Collaborations}{Collaborations}}\label{classcsmp_1_1_time_step_evaluator_collaborations}
In a typical CSMP simulation, the \doxylink{classcsmp_1_1_model}{Model} collaborates with Algorithm, \doxylink{classcsmp_1_1_interrelation}{Interrelation}, and \doxylink{classcsmp_1_1_visitor}{Visitor} objects via its \doxylink{classcsmp_1_1_model_a1f470e567edc05fb61d72ba12dbda6b8}{Apply()} and \doxylink{classcsmp_1_1_model_a2e12f259012989765f3269d8ea721092}{Accept()} interfaces, respectively. For data transfer, the \doxylink{classcsmp_1_1_model}{Model} can also exchange properties with a \doxylink{classcsmp_1_1_finite_difference_grid}{Finite\+Difference\+Grid} object using the \doxylink{classcsmp_1_1_element}{Element} interpolation functions.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}{}\doxysubsection{\texorpdfstring{Consequences}{Consequences}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}
A \doxylink{classcsmp_1_1_model}{Model} encapsulates the discretization of a geological object with associated properties. It thereby creates an interface to this object which allows to carry out computations on the object, modify property values, input and output these to other tools, and to address and manipulate sub-\/ regions of the object. Sub-\/regions can be identified on the basis of property values and they can be associated with a name. Once this is done, most of the \doxylink{classcsmp_1_1_model}{Model} interface can also be used for individual Regions.\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
The public interfaces of the \doxylink{classcsmp_1_1_model}{Model} invoke a data-\/access process for the discretized real-\/world model. The key steps in this process are\+:

(1) The Property Database is queried for the variable specifications of a variable defined as an input string (for instance "{}permeability"{}). The database returns a \doxylink{structcsmp_1_1_index}{csmp\+::\+Index} that uniquely identifies the variable for efficient access in the computations.

(2) The placement of the variable (\doxylink{classcsmp_1_1_node}{Node}, Integration\+Point or \doxylink{classcsmp_1_1_element}{Element}) determines the depth of the search for the variable in the hierarchy of the mesh in the \doxylink{classcsmp_1_1_model}{Model} object.

(3) Once a variable location object (\doxylink{classcsmp_1_1_node}{Node}, Integration\+Point, or \doxylink{classcsmp_1_1_element}{Element}) is found, its ID is used to retrieve the value or status of the variable from the Memory\+Manager via methods like \doxylink{classcsmp_1_1_local_variable_storage_a4387c2c28afd79c9142834fc4a976b48}{Read()} or \doxylink{classcsmp_1_1_local_variable_storage_a8642fe6f83bb6981e7c0d6ab5b2c0248}{Store()}. These methods are overloaded to retrieve Scalar-\/, Vector-\/, and \doxylink{classcsmp_1_1_tensor_variable}{Tensor\+Variable$<$dim$>$} instances.

(4) Within the Memory\+Manager object the variables live in STL vectors that were instantiated for the specific variable types. The length of such vectors depends on the placement of the variables. Originally the Memory\+Manager object is build for the variables that were specified in the variable database from your input file. When you create a new variable at runtime (using \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} objects), a new vector is build and inserted for this variable. The addresses of other variables remain valid in this process. Thus, you can efficiently create new variables at runtime.\hypertarget{classcsmp_1_1_visitor_examples}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{classcsmp_1_1_visitor_examples}
In the following example, the element type \doxylink{classcsmp_1_1_linear_triangle}{Linear\+Triangle} is set as default finite-\/element. A \doxylink{classcsmp_1_1_triangulator}{Triangulator} mesh generator object is used by the \doxylink{classcsmp_1_1_model}{Model} constructor to generate a mesh of triangular finite-\/elements. This mesh is build from regular-\/gridded input data for which the user is prompted and the mesh in used further to buid a \doxylink{classcsmp_1_1_model}{Model} object named \textquotesingle{}model\textquotesingle{}. In this process, the default variable text file \textquotesingle{}CSP\+\_\+variables.\+txt\textquotesingle{} is read to initialize the variable database. The porosity of the new model is set to a uniform value of 3\% and \doxylink{group___c_s_m_p__global__enumerations_gga98d2031b830da37499a1b512d9dca4b9a2d373b048f997a96c661862c40f2fcae}{DIRICH(let)} boundary conditions are applied at the model top (cross-\/sectional model). Now, instances of subclasses of Algorithms, Interrelations and Visitors are applied by \textquotesingle{}passing\textquotesingle{} them to the \doxylink{classcsmp_1_1_model}{Model}. This invokes global (mesh-\/wide) and local (finite-\/element restricted) computations. Finally the variable \textquotesingle{}temperature\textquotesingle{} is output to the HDF file \textquotesingle{}computed\+\_\+temperature\textquotesingle{}.
