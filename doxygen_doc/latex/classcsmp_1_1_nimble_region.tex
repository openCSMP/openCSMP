\doxysubsection{Detailed Description}
\subsubsection*{template$<$uint32\+\_\+t dim$>$\newline
class csmp\+::\+Nimble\+Region$<$ dim $>$}
Flexible collection of \doxylink{classcsmp_1_1_element}{Element} and \doxylink{classcsmp_1_1_node}{Node} object pointers to be used by the \doxylink{classcsmp_1_1_p_d_e___integrator}{PDE\+\_\+\+Integrator}, which also requires access to ranges of (perimeter) nodes.

\doxylink{classcsmp_1_1_nimble_region}{Nimble\+Region} is a light (non-\/unique) version of \doxylink{classcsmp_1_1_region}{Region} that can grow or shrink, retaining the knowledge of its perimeter.

Like \doxylink{classcsmp_1_1_region}{Region}, \doxylink{classcsmp_1_1_nimble_region}{Nimble\+Region} keeps track of its perimeter, which always includes a halo that comes about as all elements that contain user-\/supplied nodes (and additional ones) will be included into the contructed region.

The region is based on the STL vector and operated under a high-\/memory policy. This means that the Update() and other functions retain previous vector storage allocations, just resizing these vectors to zero when a reconstruction is performed, to avoid costly memory allocations. To delete both elements and the internal storage of the vectors, delete and create a new \doxylink{classcsmp_1_1_nimble_region}{Nimble\+Region} object.

\begin{DoxyAttention}{Attention}
\doxylink{classcsmp_1_1_nimble_region}{Nimble\+Region} does not have a name or properties of its own and it is not managed by the \doxylink{classcsmp_1_1_region_interface}{Region\+Interface}, create it using its constructor and manage it with DES or any other parallel algorithm.

Grow(), Shrink() and Change\+Shape() operations rely on the connectivity between equidimensional elements and nodes.

Thus far, Nimbleregion only works with linear elements.
\end{DoxyAttention}
