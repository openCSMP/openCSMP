\subsubsection*{template$<$uint32\+\_\+t dim$>$\newline
class csmp\+::\+Operand$<$ dim $>$}
Interface for all of CSMP\textquotesingle{}s variable types facilitating that they can be used together in computations; currently used only by \doxylink{classcsmp_1_1_interrelation}{Interrelation}; outdated design, refactoring required.

\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
Forget for a moment all about the rest of the CSMP code except for the basic variables \doxylink{classcsmp_1_1_scalar_variable}{Scalar\+Variable}, \doxylink{classcsmp_1_1_vector_variable}{Vector\+Variable} and \doxylink{classcsmp_1_1_tensor_variable}{Tensor\+Variable} and think of the possibility of creating objects that are overloaded such that you can write expressions for the whole mesh object or sub-\/regions thereof, which read like mathematical equations in which the variables refer to local or distributed data. ~\newline


This quest was the design intent of the \doxylink{classcsmp_1_1_operand}{Operand} class and it brings CSP users close to this goal when they are prepared to write their own \doxylink{classcsmp_1_1_interrelation}{Interrelation} subclasses. The goal is fully realized through the new \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} classes for use in main() programs. These are however only complementary to the \doxylink{classcsmp_1_1_operand}{Operand} and \doxylink{classcsmp_1_1_interrelation}{Interrelation} mechanism, because they do not encapsulate the calculations which Interrelations do.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}{}\doxysubsection{\texorpdfstring{Design Intent}{Design Intent}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}
Apart from being able to write mathematical expressions which are applied to the whole \doxylink{classcsmp_1_1_model}{Model} or sub-\/\+Regions thereof (as is facilitated through the \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} class), there is a need to use distributed instances of properties in calculations inside objects which are still efficient and allow the user to partially ignore variable IDs and the variable placement in the mesh (\doxylink{classcsmp_1_1_node}{Node}, Integration\+Point or \doxylink{classcsmp_1_1_element}{Element}). This requires (1) the use of a notation to represent the variable in mathematical expressions, and (2) an association of the \doxylink{structcsmp_1_1_index}{csmp\+::\+Index} of the variable with the notation such that it does not need to be requested from the \doxylink{classcsmp_1_1_property_database}{Property\+Database} every time the expression is evaluated. Finally (3), temporary variable storage is needed to allow that a value can be range-\/checked before it is written back into the \doxylink{classcsmp_1_1_model}{Model} storage. This buffer is essential when it comes to checking where in a chain of expressions, a physically meaningless value was produced.\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
Operands are used in Interrelations, Algorithms, Algorithms, and \doxylink{classcsmp_1_1_visitor}{Visitor} objects.\hypertarget{classcsmp_1_1_v_data_structure}{}\doxysubsection{\texorpdfstring{Structure}{Structure}}\label{classcsmp_1_1_v_data_structure}
The \doxylink{classcsmp_1_1_operand}{Operand} is a simple class object with a String containing its name, a \doxylink{structcsmp_1_1_index}{csmp\+::\+Index} describing the represented variable, and each one of the basic CSMP variables as well as an output condition flag which specifies the \doxylink{group___c_s_m_p__global__enumerations_ga98d2031b830da37499a1b512d9dca4b9}{VARIABLE\+\_\+\+FLAG} of the property locations which the variable is permitted to overwrite if the calculation yielded a result which is within the permitted range.\hypertarget{classcsmp_1_1_solver_participants}{}\doxysubsection{\texorpdfstring{Participants}{Participants}}\label{classcsmp_1_1_solver_participants}
A \doxylink{structcsmp_1_1_index}{csmp\+::\+Index}, a String, an output \doxylink{group___c_s_m_p__global__enumerations_ga98d2031b830da37499a1b512d9dca4b9}{VARIABLE\+\_\+\+FLAG} and CSP basic variables (\doxylink{classcsmp_1_1_scalar_variable}{Scalar\+Variable}, \doxylink{classcsmp_1_1_vector_variable}{Vector\+Variable}, and \doxylink{classcsmp_1_1_tensor_variable}{Tensor\+Variable}).\hypertarget{classcsmp_1_1_time_step_evaluator_collaborations}{}\doxysubsection{\texorpdfstring{Collaborations}{Collaborations}}\label{classcsmp_1_1_time_step_evaluator_collaborations}
Operands collaborate with CSP basic variables and the enumerations which are defined in \doxylink{_c_s_m_p__definitions_8h}{CSMP\+\_\+definitions.\+h} (e.\+g., \doxylink{group___c_s_m_p__global__enumerations_ga98d2031b830da37499a1b512d9dca4b9}{VARIABLE\+\_\+\+FLAG}...).\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}{}\doxysubsection{\texorpdfstring{Consequences}{Consequences}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}
The operators $+, -, *, /, +=, -=, *=, /= $ are overloaded for Operands such that they can interact with eachother, double data, and the CSP basic variables. One should not write expressions like A = C. Following the logic of an assignment, A = B means\+: The \doxylink{classcsmp_1_1_operand}{Operand} A now refers to exactly the same variable as B and it will also contain the same values. If \doxylink{classcsmp_1_1_operand}{Operand} A represents a property stored in the \doxylink{classcsmp_1_1_model}{Model}, the variable A will no longer exist following the assignment. ~\newline


Importantly, scalar-\/, vector-\/, and tensor variables are more than just mathematical variables in that they also contain a STATUS flag which specifies how they are treated in the assembly of the finite-\/element equations. This requires some rules about the flag assignment\+: If you say


\begin{DoxyCode}{0}
\DoxyCodeLine{A\ =\ C\ +\ B;}

\end{DoxyCode}


the temporary variable that is created will be flagged like the lefthand operator before the assigment. If $C = PLAIN$ and $B=DIRICH$, A will be $PLAIN$. If the combined operator += is used, A will retain its original flag because the assignment here uses the assignment as defined for scalar variables. ~\newline


If you compare an \doxylink{classcsmp_1_1_operand}{Operand} with a \doxylink{group___c_s_m_p__global__enumerations_ga98d2031b830da37499a1b512d9dca4b9}{VARIABLE\+\_\+\+FLAG} enumeration, the comparison will be carried out using all flag(s) of the underlying variable. Thus, if a vector variable in a 2D calculation has two different flags (for instance, a DIRICH flag for the X displacement and a PLAIN flag for the Y displacement) a comparison will evaluate as false. In this case one should use Vector\+Variable\+::\+Flag( int i) to carry out a more specific comparison. Any comparisons with not initialized Operands or Operands that store NAN values in the variables will evaluate as false.\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
By default, Operands have storage for a single variable value of type \doxylink{classcsmp_1_1_scalar_variable}{Scalar\+Variable}, \doxylink{classcsmp_1_1_vector_variable}{Vector\+Variable}, or \doxylink{classcsmp_1_1_tensor_variable}{Tensor\+Variable}, but only if this variable exists in the \doxylink{classcsmp_1_1_property_database}{Property\+Database} (in contrast, Property\+Handles spawn the generation of a new variable in the \doxylink{classcsmp_1_1_property_database}{Property\+Database} if the variable does not exist). ~\newline


The need for large computations imposes stringend constraints on the properties of Operands. They may be big in size because there will only be a few, but their overloaded operators have to be efficient since single calculations may involve millions of calls to those. Already a function call overhead is significant for the overloaded operators. To avoid this overhead auto-\/inlining is used in the compilation.

The construction of temporary \textquotesingle{}Operands\textquotesingle{} in expressions like\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{C\ =\ A\ +\ 32.5;}

\end{DoxyCode}


should also be avoided. In those cases the construction by the compiler of temporary objects (object x which will be assigned to C) can be avoided only in some cases through construction of the Operands in the return statements of the overloaded operators. ~\newline


To avoid the creation of temporaries you should rather write\+: ~\newline



\begin{DoxyCode}{0}
\DoxyCodeLine{C\ =\ 32.5;\(\backslash\)}
\DoxyCodeLine{C\ +=\ A;}

\end{DoxyCode}


Operands also store a \textquotesingle{}calculation offset\textquotesingle{} which is used by Algorithms to modify the placement of dependent variables in computations involving the \doxylink{classcsmp_1_1_operand}{Operand} variable, when coupled systems of equations are solved.\hypertarget{group___c_s_m_pglobal_enums_application}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{group___c_s_m_pglobal_enums_application}
Operands are typically used in Algorithms and Interrelations. When you derive a subclass from an \doxylink{classcsmp_1_1_interrelation}{Interrelation}, you first create a \doxylink{classcsmp_1_1_operand}{Operand} reference to a physical variable in your model\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{\mbox{\hyperlink{classcsmp_1_1_operand_a48005bae4b03d67afba4c6b0553d0d6b}{Operand}}\&\ \ K;}

\end{DoxyCode}


You then associate the \doxylink{classcsmp_1_1_operand}{Operand} with a property which has been defined before as a member of the \doxylink{classcsmp_1_1_property_database}{Property\+Database}. This happens in your interrelation constructor.


\begin{DoxyCode}{0}
\DoxyCodeLine{K(\ GlobalProperty(\textcolor{stringliteral}{"{}conductivity"{}})\ )}

\end{DoxyCode}


This defines K as a notation for \textquotesingle{}conductivity\textquotesingle{}. You can now use K in expressions using CSMP basic variables and other Operands\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{K\ +=\ PHI\ /\ 322.1\ -\/\ 45.0;}

\end{DoxyCode}

Whether this comparison is meaningful, depends on the variable types on the left and right-\/side of the comparitors, and errors will be reported for obviously nonsensical comparisons. Comparisons of variables of the same type are straightforward and the comparison of a \doxylink{classcsmp_1_1_scalar_variable}{Scalar\+Variable} with a double is as well.

If a vector variable is compared with a scalar, this implementation of comparitors will compare the length of the vector with the scalar, since in most cases this is a physically sensible thing to do. ~\newline
