\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
To encapsulate the integration / numerical solution of partial-\/differential equations (PDE). This process entails

(0) the creation of a sparsity pattern (1) the assembly of a sparse solution matrix, G, using integral contributions from finite elements or finite volumes, (2) the assembly of a right-\/hand vector with essential and initial conditions; before, Dirichlet conditions are eliminated. (3) Inversion of the matrix equation Ax=b to find the solution vector x. (4) Mapping the results from the result vector \textquotesingle{}x\textquotesingle{} back onto the mesh, performing range checks.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}{}\doxysubsection{\texorpdfstring{Design Intent}{Design Intent}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}
The \textquotesingle{}strategy\textquotesingle{} design pattern is used to separate the PDE operator / integrator implementation from the the type of finite element(s) or FV\textquotesingle{}s used and the solution method chosen. As a consequence, the same PDE operator objects and solution methods can be used for a range of computational cell types with different node numbers and so forth. The Bridge pattern is used to decouple specific cell types and interpolation orders from the way the contributions from the finite elements are integrated. These implementations are found in collections of subclasses of the \doxylink{classcsmp_1_1_math_operator_l_h_s}{Math\+Operator\+LHS} and \doxylink{classcsmp_1_1_math_operator_r_h_s}{Math\+Operator\+RHS}, which are grouped together in specific PDE operator libraries. These are further subdivided into ones for analytic and others for numeric integration.

The \doxylink{classcsmp_1_1_p_d_e___integrator}{PDE\+\_\+\+Integrator} class is a base class from which specific \doxylink{classcsmp_1_1_p_d_e___integrator}{PDE\+\_\+\+Integrator} subclasses can be inherited. These subclasses are found in the pde\+\_\+integrators directory in the source. Subclasses are implemented to support nonlinear iteration loops and more user-\/friendly high-\/level forms of integrators like the \doxylink{classcsmp_1_1_steady_state_diffusor}{Steady\+State\+Diffusor}.\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
\doxylink{classcsmp_1_1_p_d_e___integrator}{PDE\+\_\+\+Integrator} supports the solution of elliptic, parabolic and even hyperbolic PDEs in 2D and 3D . These computations can be targeted on the entire \doxylink{classcsmp_1_1_model}{Model}, Regions thereof and \doxylink{classcsmp_1_1_boundary}{Boundary} objects..\hypertarget{classcsmp_1_1_p_d_e___integrator___c_r_m_participant}{}\doxysubsection{\texorpdfstring{Participants}{Participants}}\label{classcsmp_1_1_p_d_e___integrator___c_r_m_participant}
Each \doxylink{classcsmp_1_1_p_d_e___integrator}{PDE\+\_\+\+Integrator} contains maps of pointers to left and righthand operators that are inherited from the \doxylink{classcsmp_1_1_math_operator_l_h_s}{Math\+Operator\+LHS} and \doxylink{classcsmp_1_1_math_operator_r_h_s}{Math\+Operator\+RHS} base classes. Other variables set the state of the algorithm, the time\+\_\+increment in transient calculations and so forth.

To solve the system of equations, the \doxylink{classcsmp_1_1_p_d_e___integrator}{PDE\+\_\+\+Integrator} uses a \doxylink{classcsmp_1_1_solver}{Solver} object. Different solvers can be configured, applied and managed via the Strategy pattern as described in the users guide.\hypertarget{classcsmp_1_1_time_step_evaluator_collaborations}{}\doxysubsection{\texorpdfstring{Collaborations}{Collaborations}}\label{classcsmp_1_1_time_step_evaluator_collaborations}
\doxylink{classcsmp_1_1_p_d_e___integrator}{PDE\+\_\+\+Integrator} interact with \doxylink{classcsmp_1_1_model}{Model}, \doxylink{classcsmp_1_1_region}{Region}, \doxylink{classcsmp_1_1_boundary}{Boundary} and \doxylink{classcsmp_1_1_split_boundary}{Split\+Boundary} objects. It queries these objects for the data needed to setup the solution matrices and vectors. It also uses them to managed evolving boundary conditions, including ones needed to dynamically couple domains together.

\doxylink{classcsmp_1_1_p_d_e___integrator}{PDE\+\_\+\+Integrator} also collaborates with the \doxylink{classcsmp_1_1_mesh_manager}{Mesh\+Manager} and the \doxylink{classcsmp_1_1_property_database}{Property\+Database} to gain access to variables and finite elements (\doxylink{classcsmp_1_1_element}{Element} class instances).

\doxylink{classcsmp_1_1_p_d_e___integrator}{PDE\+\_\+\+Integrator} obtains the finite-\/element contributions from the \doxylink{classcsmp_1_1_element}{Element} class that in turn has access to specific finite-\/element functionality via its FE policy. The interior workings of this remain hidden behind the interface of the specific element that is assembled. This is implemented as based on a \textquotesingle{}bridge\textquotesingle{} pattern.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}{}\doxysubsection{\texorpdfstring{Consequences}{Consequences}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}
The design as a full-\/function base class implies that to create a PDE operator subclass one only has to overwrite those methods that one wants to modify. Other code does not need to be modified. To create additional PDE operators, inherit these from \doxylink{classcsmp_1_1_math_operator_l_h_s}{Math\+Operator\+LHS} or \doxylink{classcsmp_1_1_math_operator_r_h_s}{Math\+Operator\+RHS}.\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
