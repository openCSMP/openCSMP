class csmp\+::\+Property\+Database$<$ dim $>$}

\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
To manage access to physical variables in the numerical simulation. Depending on their purpose such variables have a different type such as scalar, vector, tensor or array. In addition, they have a different placement in the mesh\+: model, region, element node etc. Thus, housekeeping is required to keep track of such different variables. Firstly, one must be able to search for them by name. Secondly, their values have to be checked against a physically meaningful range. Thirdly, one needs to know how a variable was defined (as a scalar, vector or tensor) and at which locations in a discretization it shall be computed (nodes, integration points or elements etc.). To accomplish this there must be a unique access key for each variable in order to retrueve it in a computationally efficient way.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}{}\doxysubsection{\texorpdfstring{Design Intent}{Design Intent}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}
The design intent of the \doxylink{classcsmp_1_1_property_database}{Property\+Database} is to have a single object in the CSMP code which manages the physical variables of a simulation and can be queried for their type, placement, and property index. These three characteristics combine into the structure \doxylink{structcsmp_1_1_index}{csmp\+::\+Index} which serves the role of an access keys to distributed variable values.

The records in the \doxylink{classcsmp_1_1_property_database}{Property\+Database} are \doxylink{structcsmp_1_1_parameter}{Parameter} class instances which contain the variable name, its \doxylink{structcsmp_1_1_index}{csmp\+::\+Index}, and a physically meaningful range for each variable. This range can be queried to test whether implausible results were computed.

Finally, the database must ascertain uniqueness of the variable \textquotesingle{}string\textquotesingle{} identifiers and allow to retrieve these in a reverse approach, starting from the inside of a computation in which only the efficient access keys are known. This capability is needed for error reporting.

The creation or deletion of variables at runtime is a further task of the \doxylink{classcsmp_1_1_property_database}{Property\+Database}.\hypertarget{classcsmp_1_1_v_data_structure}{}\doxysubsection{\texorpdfstring{Structure}{Structure}}\label{classcsmp_1_1_v_data_structure}
The \doxylink{classcsmp_1_1_property_database}{Property\+Database} represents a binary tree of fixed-\/size physical-\/variable records which are accessed via name strings. Access of variable specifications benefits from the tree structure, but the reverse search for a variable name using the \doxylink{structcsmp_1_1_index}{csmp\+::\+Index} as a key has a linear time complexity. Due to the typically small number of physical variables in a model, this is not important.\hypertarget{classcsmp_1_1_solver_participants}{}\doxysubsection{\texorpdfstring{Participants}{Participants}}\label{classcsmp_1_1_solver_participants}
The \doxylink{classcsmp_1_1_property_database}{Property\+Database} uses \doxylink{structcsmp_1_1_parameter}{Parameter} class objects as variable records. These are accessed by the variable names which are stored in std\+::string objects.\hypertarget{classcsmp_1_1_time_step_evaluator_collaborations}{}\doxysubsection{\texorpdfstring{Collaborations}{Collaborations}}\label{classcsmp_1_1_time_step_evaluator_collaborations}
The \doxylink{classcsmp_1_1_property_database}{Property\+Database} is a data member of the \doxylink{classcsmp_1_1_model}{Model} object and collaborates with \doxylink{structcsmp_1_1_index}{Index} and \doxylink{structcsmp_1_1_parameter}{Parameter} records.

\begin{DoxyAttention}{Attention}
The \doxylink{classcsmp_1_1_property_database}{Property\+Database} does not store any variable values! These are stored in the \doxylink{classcsmp_1_1_local_variable_storage}{Local\+Variable\+Storage} associated with the basic tree objects\+: \doxylink{classcsmp_1_1_node}{Node}, \doxylink{classcsmp_1_1_element}{Element}, etc.
\end{DoxyAttention}
\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}{}\doxysubsection{\texorpdfstring{Consequences}{Consequences}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}
As is described in the CSMP User\textquotesingle{}s Guide, properties of a physical variable and \doxylink{structcsmp_1_1_index}{csmp\+::\+Index} structures can be obtained from the \doxylink{classcsmp_1_1_property_database}{Property\+Database}. As additional functionality, the \doxylink{classcsmp_1_1_property_database}{Property\+Database} can be used for unit conversions and to add or delete physical variables at runtime.\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
The \doxylink{classcsmp_1_1_property_database}{Property\+Database} contains an STL map of variable names serving as keys to \doxylink{structcsmp_1_1_parameter}{Parameter} objects which hold the variable specifications. The variable names are stored in the map in alphabetical order and the map is initialized from a text file when the \doxylink{classcsmp_1_1_property_database}{Property\+Database} is constructed. After all variable records have been added to the map, they are counted and \doxylink{structcsmp_1_1_index_a16dd82c3058e3f91a76485a2bb574efb}{csmp\+::\+Index.\+index} integers are issued. These indices are used to access the right \doxylink{classcsmp_1_1_local_variable_storage}{Local\+Variable\+Storage} object.\hypertarget{classcsmp_1_1_visitor_examples}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{classcsmp_1_1_visitor_examples}
