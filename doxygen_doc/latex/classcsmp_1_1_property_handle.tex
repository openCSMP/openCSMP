\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
Especially for test computations, one would like write arithmetic expressions which apply to distributed physical variables. To make these expressions concise it is useful to replace lengthy variable names by a notation of choice, for instance, to define a variation of porosity with depth\+:

phi = phi -\/ 1 / z\texorpdfstring{$^\wedge$}{\string^}2

Finally, there is a need to create variables for such mathematical expressions at runtime.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}{}\doxysubsection{\texorpdfstring{Design Intent}{Design Intent}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_design}
The \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} was designed following the motivation from above, but also by using the existing \doxylink{classcsmp_1_1_operand}{Operand} classs as a model. Thus, an \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} shares many of the \doxylink{classcsmp_1_1_operand}{Operand} interfaces, but as a difference, it will currently apply to the associated variable on all the elements, nodes, or constraint points of a mesh, depending on where the \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} variable is placed.

The desired capability of writing arithmetic expressions is implemented via C++ operator overloading. Notably, there is no assignment operator for operands to operands, since the expected result of a C++ assignment would imply a complete overwriting of the lefthand physical variable with the one on the right of the assignment operator.

Self-\/assignment is provided to write expressions which are efficient, since they do not require the creation of temporary variables. Thus, the expression

phi = phi -\/ 1 / z\texorpdfstring{$^\wedge$}{\string^}2

can be replaced by

phi -\/= 1 / z\texorpdfstring{$^\wedge$}{\string^}2

which avoids the creation of a temporary variable for the righthand side which would subsequently be assigned to \textquotesingle{}phi\textquotesingle{} on the left.\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
Property\+Handles can be applied anywhere in a main program or a high-\/level class object or function which has access to the CSMP library. To create a \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} its constructor takes arguments which allow it to associate itself with an existing variable in the \doxylink{classcsmp_1_1_model}{Model} or to request a new \doxylink{classcsmp_1_1_model}{Model} variable which will be globally known until the \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} is destructed again. If a new variable is created, it will be destroyed when the destructor of the \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} is called.\hypertarget{classcsmp_1_1_solver_participants}{}\doxysubsection{\texorpdfstring{Participants}{Participants}}\label{classcsmp_1_1_solver_participants}
The \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} has references to the Mesh and Memory managers, and the \doxylink{classcsmp_1_1_property_database}{Property\+Database} and it stores the \doxylink{structcsmp_1_1_index}{csmp\+::\+Index} of the associated physical variable for rapid variable access.\hypertarget{classcsmp_1_1_time_step_evaluator_collaborations}{}\doxysubsection{\texorpdfstring{Collaborations}{Collaborations}}\label{classcsmp_1_1_time_step_evaluator_collaborations}
The \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} collaborates with the \doxylink{classcsmp_1_1_model}{Model} and its contained managers in order to carry out its arithmetic operations.\hypertarget{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}{}\doxysubsection{\texorpdfstring{Consequences}{Consequences}}\label{classcsmp_1_1_two_phase_implicit_node_centered_f_v_transport_consequences}
Property\+Handles allow the user to add, subtract, multiply, and divide distributed physical variables among eachother, to assign values to them, or to add, subtract, multiply, and divide CSP basic variables to the distributed physical variables.\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
For clarity, the placement and type of the physical variables which are associated with Property\+Handles are used to impose restrictions on whether Property\+Handles can be used together in arithmetic expressions. Only if the placement and variable type is the same this can be done.

The user is requested to make recommendations of how Property\+Handles can be made more flexibility while avoiding ambiguities of assigning variables of different type to one another.\hypertarget{classcsmp_1_1_visitor_examples}{}\doxysubsection{\texorpdfstring{Application Examples}{Application Examples}}\label{classcsmp_1_1_visitor_examples}

The interrelation Assign\+Depth\+To\+Property assigns the z-\/coordinate of the element centers to the new variable \textquotesingle{}depth\textquotesingle{}. Constructor associates a distributed physical variable with the constructed \doxylink{classcsmp_1_1_property_handle}{Property\+Handle}. If the variable already exists in the \doxylink{classcsmp_1_1_property_database}{Property\+Database}, the new \doxylink{classcsmp_1_1_property_handle}{Property\+Handle} will be a handle to it. If the variable name is not known to the \doxylink{classcsmp_1_1_property_database}{Property\+Database}, it will be registered as a new variable and property storage will be allocated accordingly by the Memory\+Manager.\hypertarget{group___c_s_m_pglobal_functions_arguments}{}\doxysubsection{\texorpdfstring{Input Arguments}{Input Arguments}}\label{group___c_s_m_pglobal_functions_arguments}
There are four constructor arguments. The first is a reference to the current \doxylink{classcsmp_1_1_model}{Model}, the second is the variable name, and the remaining two arguments specify the variable type and placement, respectively. These last two arguments have the default values SCALAR, and NODE. If the variable type or placement differs from these values, they must be specified. If a new variable shall be created the user must specify its type and placement.\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
The constructor initializes the output variable flag to PLAIN and requests the \doxylink{structcsmp_1_1_index}{csmp\+::\+Index} for the associated variable from the \doxylink{classcsmp_1_1_property_database}{Property\+Database}.
