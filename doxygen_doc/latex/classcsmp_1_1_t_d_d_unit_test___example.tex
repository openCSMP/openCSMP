\doxysubsection{Detailed Description}
Introduces to \doxylink{classcsmp_1_1_test}{Test} Driven Development in general and attempts to provide a CSMP++ specific approach. 

Unit\+Tests and \doxylink{classcsmp_1_1_test}{Test} Driven Development increase confidence in the code you write and drastically reduce debugging needs. In an environment like CSMP that is not tested bottom up, a different approach to testing new classes may be chosen. Also for classes that act on a \doxylink{classcsmp_1_1_model}{csmp\+::\+Model}, the user might skip test driven development/unit testing due to the high effort required. This document tries to provide an approach to CSMP specific TDD.

\hypertarget{classcsmp_1_1_t_d_d_unit_test___example_general}{}\doxysubsubsection{\texorpdfstring{In general XP}{In general XP}}\label{classcsmp_1_1_t_d_d_unit_test___example_general}
A Unit \doxylink{classcsmp_1_1_test}{Test} is designed to test the interface of a single class through proper pass/fail criteria. A Functional \doxylink{classcsmp_1_1_test}{Test} tests the result of class interactions within a bigger context. Hence, pass/fail criteria are more complex. This also includes performance test and the validation of applications in their whole.\hypertarget{classcsmp_1_1_t_d_d_unit_test___example_csmp}{}\doxysubsubsection{\texorpdfstring{Interpreted for CSMP}{Interpreted for CSMP}}\label{classcsmp_1_1_t_d_d_unit_test___example_csmp}
To test classes that require a model to act on, multiple Unit Tests may be run within one test function and work with the same model. Classes are tested indepently from another, and the \doxylink{classcsmp_1_1_test_suite}{Test\+Suite} will spot failures individually. To sum it up, we put multiple tests inside a single test function that establishes a model for all of them. This is done to reduce the effort that goes into creating a test. Functional Tests, or \doxylink{classcsmp_1_1_test}{Test} Cases, measure performance and compare results of complex applications.\hypertarget{classcsmp_1_1_t_d_d_unit_test___example_tdd}{}\doxysubsection{\texorpdfstring{Introduction to TDD}{Introduction to TDD}}\label{classcsmp_1_1_t_d_d_unit_test___example_tdd}
Write your Unit \doxylink{classcsmp_1_1_test}{Test} first, let it fail(because there is no class yet, afterall) then implement your class piecewise to make the tests pass. Once the tests pass, improve your code. Benefits\+:
\begin{DoxyItemize}
\item improves design
\begin{DoxyItemize}
\item think it through
\item then implement
\end{DoxyItemize}
\item reduces amount of code
\begin{DoxyItemize}
\item by sticking to what you really planned to do
\item by having code that does the job quickly
\begin{DoxyItemize}
\item and improve it when there\textquotesingle{}s time
\end{DoxyItemize}
\end{DoxyItemize}
\item used together with SVN, often replaces debugger
\begin{DoxyItemize}
\item revert to revision that works, go form there
\end{DoxyItemize}
\item YOU CAN TRUST IN YOUR CODE AN SUBSEQUENT USE OF IT
\item IT IS TESTED(what\textquotesingle{}s the alternative?)
\end{DoxyItemize}

How it\textquotesingle{}s done\+:
\begin{DoxyEnumerate}
\item Write your test
\item See it fail
\item Implement your code
\item Make the test pass
\end{DoxyEnumerate}\hypertarget{namespacecsmp_implementation}{}\doxysubsection{\texorpdfstring{Implementation}{Implementation}}\label{namespacecsmp_implementation}
