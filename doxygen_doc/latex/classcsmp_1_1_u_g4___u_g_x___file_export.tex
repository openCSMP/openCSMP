class csmp\+::\+UG4\+\_\+\+UGX\+\_\+\+File\+Export$<$ dim $>$}
Export interface for writing text files in the .ugx format using XML for the formatting. Explanations of the UG4 output tags.

Drawing on the information provided in \textquotesingle{}file\+\_\+io\+\_\+ugx\texorpdfstring{$\ast$}{*}\textquotesingle{} in conjunction with the Grid\+Writer\+UGX class. Some enumerations in grid/grid\+\_\+base\+\_\+objects.\+h

To assign properties to the grid, attachment traits are used. These are\+: vertex, edge, face and volume.

\begin{DoxyAttention}{Attention}
Design choices had to be made to crerate the additional edge and face data that UG4 needs for during the output\+:
\end{DoxyAttention}
Importantly, CSMP models store edges and faces only if these are needed as lower-\/dimensional entities for computations (well and fracture modelling, assignment of boundary condtions etc.). In UG4 they are always needed and their numbering must be unique.

The choice made for the implementation of this CSMP-\/\+UG4 interface is that those edges and faces that are present in the CSMP model are later identified in the edges and faces vectors created for UG. What is output is the "{}model domain"{} plus the faces (and interfaces) touching it. Their \textquotesingle{}idx\textquotesingle{} is mapped that of the edge and faces created for UG.

\doxylink{classcsmp_1_1_region}{Region} and \doxylink{classcsmp_1_1_boundary}{Boundary} output enlists all the nodes, edges and faces that belong to these, although UG4 only wants them to be listed once. Here, the feature in Promesh which eliminates excess edges and faces is relied upon.

\begin{DoxyAttention}{Attention}
properties are no associated with regions but communicated as node, edge, face and volume attachments. Since the CSMP model only contains property values for those elements, faces, interfaces and nodes present in there, no-\/data values are printed for all the other ones needed by UG.
\end{DoxyAttention}
