\hypertarget{compare_floats_8h_motivation}{}\doxysubsection{\texorpdfstring{Motivation}{Motivation}}\label{compare_floats_8h_motivation}
Mesh connectivity usually termed as \doxylink{classcsmp_1_1_v_data}{VData} typically consists of lists of (1) node and constraint-\/point coordinates (constraint points can be nodes between nodes but also integration points), (2) a listing of the nodes which belong to each element, and (3) a list of the neighbors of each element. If the element lies on the model boundary and there is no neighbor then entries in this list will be UNSPECIFIED. (4) A typical \doxylink{classcsmp_1_1_v_data}{VData} set also specifies which nodes lie at the model boundary and which property values apply to these nodes.

The class \doxylink{classcsmp_1_1_v_data}{VData} brings all these datasets together into an object which holds the information to build this V-\/type mesh connectivity.\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
\doxylink{classcsmp_1_1_v_data}{VData} can be used as isolated object but it is also integrated into the \doxylink{classcsmp_1_1_v_set}{VSet} which also holds property data which are assigned to the mesh.\hypertarget{classcsmp_1_1_v_data_structure}{}\doxysubsection{\texorpdfstring{Structure}{Structure}}\label{classcsmp_1_1_v_data_structure}
The \doxylink{classcsmp_1_1_v_data}{VData} object contains coordinate objects, deques of vectors to store the connectivity and maps to hold the boundary flags and boundary values.

Detailed content\+:

(double) px, py, pz\mbox{[}0..n-\/1\mbox{]} = coordinates of n nodes (= FE vertices)

(int8\+\_\+t) bflags\mbox{[}0..n-\/1\mbox{]} = negative numbers for nodes at boundary, see later

(enum int8\+\_\+t) pelmt\mbox{[}0..e-\/1\mbox{]} = \doxylink{group___c_s_m_pglobal_enums_ga182d1fe97a0151d464d8170c0fafa872}{CSMP\+\_\+\+FEM\+\_\+\+TYPE} of e finite elements (1 entry only for single element-\/type mesh)

(size\+\_\+t) plist\mbox{[}0..e \texorpdfstring{$\ast$}{*}\mbox{[}sum npe\mbox{[}e\mbox{]}\mbox{]}\mbox{]} = nodes making up each element

(int64\+\_\+t) pfverts\mbox{[}0..e \texorpdfstring{$\ast$}{*}\mbox{[}sum fpe\mbox{[}e\mbox{]}\mbox{]}\mbox{]} = neighbor elements adjacent to the faces of each element

For \doxylink{classcsmp_1_1_face}{Face} and \doxylink{classcsmp_1_1_inter_face}{Inter\+Face} objects, \textquotesingle{}pfverts\textquotesingle{} also contains the indices of the higher-\/dimensional neighbor element.

aligns potential line elements in a 2D mesh, those at boundary are given the same orientation as the surface-\/element boundary faces 

To ensure that the normals pointing out of a lower (1D) dimensional elements located at the model boundary, and that they all point in the same direction for internal boundaries, the nodes of such elements must be locally ordered consistently; meaning these line elements are aligned with the node-\/numbering of the faces of 2D surface elements located at the model boundary whose nodes are numbered counter clockwise.

Line elements must be oriented in a consistent way for internal 1D regions or along the boundaries of a2D domain. This method accomplishes this.

The normals of the line elements are found by 90-\/degrees clockwise rotation of the tangent vector of the line elements, which points from node 0 to node 1 (in a Linear or Quadratic Line \doxylink{classcsmp_1_1_element}{Element}).

\begin{DoxyAttention}{Attention}
this method expects that there already is connectivity information for line elements

if the line elements do not know their neighbors already, this method will not work!

assumes node numbering in \textquotesingle{}plist\textquotesingle{} follows the convention corner nodes first, then Interior nodes.

method assumes that all manifolds (connections of more than 2 line elements at a node have been removed =disambiguated before. Thus it relies on a valid neighbor connectivity of the line elements, which must stored in pfverts.

the neighbors of line elements are situated opposite to its corner nodes (like for other simplex elements)
\end{DoxyAttention}
\begin{DoxyNote}{Note}
algorithmic procedure\+: 1) chains of connected line elements are found and stored in a map, using their "{}root"{} nodes as keys. 2) these are then traversed, flipping nodes whenever successive elements are not aligned. 3) at the model boundaries, the chains of line elements are flipped if their direction is not matched with that of the faces of the surface elements at the model boundary. 4) line element chains inside of the model are kept in whichever, yet consistent orientation.
\end{DoxyNote}
