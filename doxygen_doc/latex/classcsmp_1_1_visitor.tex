\doxysubsection{Detailed Description}
\subsubsection*{template$<$uint32\+\_\+t dim$>$\newline
class csmp\+::\+Visitor$<$ dim $>$}
Visitors are designed to facilitate computations on any of the objects that are contained inside a \doxylink{classcsmp_1_1_model}{Model}. Thus, one may for instance derive an equation of state type visitor to go around the nodes looking up pressure and temperature and use this information to calculate nodal fluid densities. As an important difference to Interrelations, visitors are not restricted to the computation of a single variable and they can also be used to gain access to the full finite-\/element or finite-\/volume functionality of CSMP. Thus, one can use a visitor to find a specific finite element that contains a user-\/specified point. This is done by across mesh traversal. In contrast, interrelations are restricted to sequential node-\/by-\/node, element-\/by-\/element calculations. ~\newline

To make the classical \doxylink{classcsmp_1_1_visitor}{Visitor} design pattern available to CSMP users (for documentation of pattern, refer to Gamma et al. 1996, Addison and Wesley, p. 331).\hypertarget{classcsmp_1_1_visitor_applicability}{}\doxysubsection{\texorpdfstring{Applicability}{Applicability}}\label{classcsmp_1_1_visitor_applicability}
Visitors in CSMP are designed to allow visitations of the \doxylink{classcsmp_1_1_model}{Model} hierarchy of objects\+: \doxylink{classcsmp_1_1_model}{Model} \texorpdfstring{$>$}{>} \doxylink{classcsmp_1_1_region}{Region} \texorpdfstring{$>$}{>} \doxylink{classcsmp_1_1_element}{Element} \texorpdfstring{$>$}{>} \texorpdfstring{$>$}{>} \doxylink{classcsmp_1_1_node}{Node}, as well as interfaces. The user can derive visitors from this base class in order to perform different operations on any of the objects encountered during a visitation. ~\newline

Since the argument is the actual object, its entire interface is accessible to the visitor in order to carry out operations.
